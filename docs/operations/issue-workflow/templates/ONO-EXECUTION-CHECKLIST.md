# OnO 逐组执行清单（关联 Issue 分组）

按[主规范](../README.md)、[方案](ONO-PLAN.md)和[评论模板](ONO-COMMENTS.md)填写。dot 唤醒模式简化已随 PR #21 合入，本修订定义分组规则，生效以实际 main 版本及用户授权为准。本清单记录事实，不是独立执行器，也不创造批准。

## 1. 当前事实记录

| 字段 | 填写内容 |
|---|---|
| 目标与来源 | 仓库、本组全体 Issue、主方案 Issue、互链、分组理由、实现 PR、分支；规范固定版本、唯一任务/协调者与 state revision |
| 当前状态 | 状态、更新时间、最后完整读取时间；是否暂停/撤回/提前关闭 |
| 范围与方案 | 逐 Issue 范围/验收、可叠加分类、非目标、本组统一方案版本、实际附件URL插入后的摘要、图清单、反馈处理 |
| 准确代码 | 完整 head/base/tested/main/candidate SHA；不适用写原因 |
| 授权包 | 准确动作/范围/条件/不包含项；方案、追加范围、合入收尾、例外、发布分别记录 |
| 原始批准 | 请求与回复 comment ID/URL、全文、作者login/数字ID、创建/编辑时间、发言时目标、来源验证依据、有效性 |
| 自发排除 | 新旧标识、自发comment准确ID/正文/时间/工具结果；缺日志不能断言真人 |
| 证据与结果 | 分类/共同检查、通过/失败/跳过/未覆盖；新旧失败、run/attempt、来源/hash/真实视觉/访问/到期 |
| 操作与恢复 | 幂等键、意图、前置状态/SHA、返回ID、未知结果、读回与暂停/恢复条件 |
| 阻碍与下一步 | 已授权可继续、必须停的依赖、只需用户决定的最小问题 |

普通产品组按两关推进：方案、准确 PR/head 及逐 Issue 关闭范围的合入收尾包；正常不新增第三次关单确认。单 Issue 默认也是一组；每组默认一个实现 PR，保留各 Issue 与逐项验收。PR 技术信息指回主方案 Issue，不要求换渠道再批准。此表是记录，不是身份认证或批准来源。

## 2. 每轮全量检查，开工与恢复先读取

- [ ] 每轮全量检查候选 Issue、活动组及相关 PR，读取当前时间、仓库/连接身份、适用指令与规范、实时 main/head、完整最新讨论、CI、批准及写入回执；不只看当前单，记录最后读取时间。
- [ ] 按同一功能、强依赖或适合共同验收分组，不打包无关需求；核对全体成员、逐 Issue 范围与验收，选定主方案 Issue 并互链。
- [ ] 沿用同一正式任务和唯一协调者；读取唯一简短state的活动组、成员/主方案 Issue/revision，写前核对预期版本、写后核查回执。已有活动执行或冲突就恢复/停止重复推进；无原子CAS不谎称已有，不另建分布式锁服务。
- [ ] 恢复不复述缓存的“待批准”，不沿用旧结果；读取不全停相关写动作。
- [ ] 查基线已有失败/覆盖并与本次增量分开；一次一个产品开发组，其他排队；独立分析可并行。
- [ ] 终止/撤回立即停相关推进；重开不恢复旧批准；陈旧锁不自动抢占。

## 3. 设计与方案批准

- [ ] 分类、目标/非目标、风险、实现和验收完整；设计准备/原型/反馈/图片公开授权集中明确。
- [ ] UI 先独立高保真，正文与主方案 comment 集中实嵌本组全部相关图；成员 Issue 保留沟通并保留/更新对应实嵌图、互链，同图复用原生附件URL、不重复上传；版本/内容/访问已核，不以跨 Issue 链接或无图准备说明过门。
- [ ] 方案修订不等于产品实现；中文回应每轮反馈、更新相关图，设计 Draft 仅可选辅助，无先merge门槛。
- [ ] PNG 不入Git/不备份；旧 renderer 入口已退役，历史安全边界不放宽。
- [ ] 主方案 comment 列全体成员、统一版本、逐 Issue 范围与验收、全部相关图及摘要；其余 Issue 互链；末尾一条短回复例句。
- [ ] 原始批准作者/ID/全文/时间/唯一目标及可信来源已核；排自发/引用/模板；无标识/未命中日志不是充分真人证明。
- [ ] 短回复只能绑定发言时唯一明确动作；整组请求可一次批准全组，单 Issue 批准不延伸到其他成员；“请留意见”后的OK不推合入；疑点在主方案 Issue 最小澄清。
- [ ] 组成员或范围变化先重核方案批准，新增或实质变化重新请求批准；不把历史单 Issue 批准自动升级为整组批准。

## 4. 授权范围内连续完成

- [ ] 方案批准后云端独立分支实现/测试/普通回归修复，完成后提交Draft实现PR；只能PR触发的检查如实补齐。
- [ ] 同一已授权动作不重复问；范围外缺陷、新权限/费用/风险、实质需求变化或证据例外集中追加批准。
- [ ] 实际UI覆盖焦点/hover/键盘、取消/关闭重开、主题/窗口；保存有界读回业务字段、id/元数据，再真实重载/重启，不只数量/toast。
- [ ] 跨平台语义、错误路径及合法边界具备修前/修后证据；不放宽断言或新增跳过漂绿。
- [ ] Windows同一准确提交的真实文件symlink和父目录junction反例确实运行并拒绝不安全路径；不能运行/失败则保留最小Linux兜底，不放松守卫或改安全设置。
- [ ] 写入超时先查结果；确认可恢复故障才有界重试；权限/安全拒绝不换路绕过。

## 5. 最终合入收尾审批

- [ ] 最新head/base/tested/run/attempt记录一致；元数据不一致已核checkout/父提交/树并披露。
- [ ] Windows共同检查及分类专项分列通过/失败/跳过/未覆盖；若保留Linux兜底则单列，新旧失败明确；基线红不能默许合并。
- [ ] 真实实现截图逐张对照；设计图不冒充运行图；一轮证据≤20MB、临时artifact3天、不额外备份。
- [ ] 图片全链路按本来源预检；上传失败类别、有限重试与当前可复核性照实；明确单次例外前缺口不自动豁免。
- [ ] 主方案 Issue 请求写准确 PR 编号、完整 head 及可用唯一短 SHA，一次列“合入→实际main验证→逐 Issue 条件满足后关单”；逐项明确拟关闭编号、各自检查/交付/证据条件，未列成员保持开放；不发版；合格已合入需求分支另按主规范第8节新的清理授权处理。
- [ ] 枚举本组各 Issue 关联实现/设计/试验PR，记录实际状态、merged证据、保留理由或过时依据；如需关闭过时辅助PR，在收尾包内列准确编号和仅关闭/保留分支历史的范围，不混入其他任务PR。
- [ ] 核实原始批准与整包范围；已经明确有效覆盖的关单不重复请求授权；没包含关单就不从历史merge批准推定。
- [ ] 执行前fresh read撤回/编辑/Issue/head/base/冲突/CI/证据；新head重批；base漂移重验并判断批准影响。

## 6. 合后验证与终态

- [ ] 合入调用绑定expected head；读回实际main/树；写入未知先查实际结果。
- [ ] 等真实main已配置的完整平台检查与本功能终态，不沿用PR旧结果；失败保持阻塞，范围外修复另批，不擅自回滚。
- [ ] 逐 Issue 核对关闭范围，该 Issue 关单已授权且各自条件实际满足时直接关闭，不再询问同一关单；例外来源/范围保留，未做项不改成通过。
- [ ] 关单前fresh read关联PR清单；已批准关闭的过时PR记录结果，未批准的保留并说明待决定，不自动关PR，不删除未合入分支、不误合过时设计代码。#13收尾不包括#15/#20；此条不追溯授权关闭#16。
- [ ] 主方案 Issue 报告逐 Issue 结果、证据和剩余风险，成员互链；已过期artifact只标当前不可复核，不否定历史真实测试。
- [ ] 按主规范第8节核对新的原始清理授权及后续保留/撤回要求；逐条记录准确分支/head、PR实际merged到main/合入SHA、真实main完整CI通过，无未合入新提交、其他开放PR（head/base）或活动写入/共享用途；完整分页，不凭closed或旧缓存。
- [ ] 排除main、state、受保护及共享/活跃分支；squash/rebase核对PR合入记录和当前head，任何不明/未合入项保留。删除前fresh read，支持时优先expected head/lease；UI无此能力时仅由唯一协调者在无活动写入者前提下，操作紧前重读准确head/用途/依赖并核对实际可见目标，注明非原子CAS；漂移/未知/并发风险则保留报告。读回删除结果，未知先查、不删重建同名分支；保留完整head与正常恢复路径，不永久清除历史。
- [ ] 报告已删/保留及理由，清理阻塞不改写产品交付状态；不启用仓库级自动删分支或新增workflow。不从历史批准推定删除；没有独立授权不发布；设计准备合入不关闭产品Issue；重开不自动恢复。
- [ ] 记录消费/回执/未知项；没有持久执行器时不声称完成自动锁释放或跨进程一次消费。

## 能力分层与本轮边界

每项标“规范已写/候选”“dot实际执行”“实际workflow代码强制”“已退役历史实验”，详见[准备清单](../../../archive/ono/automation-readiness-2026-10-12.md)。正式任务只唤醒dot按规范连续办事，不把每个工程步骤变成新用户关口；正常两关与来源核验保持。旧 core/专用模拟测试/policy fixture 已退役，PNG解码器及试点安全回归保留；不推进 PR20 或新协调器，也不推定其当前状态，不要求迁 pin 或补分布式执行器。任务启用须核对实际配置，不由此文档宣称已生效。
