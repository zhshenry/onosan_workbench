# 常驻 AI 助手设计方案 v1

日期：2026-09-28；对象跟随与参考读取更新：2026-09-30。状态：**方向已确认，核心交互已接入正式页面；高保真保留为设计对照**。

## 1. 目标与评审入口

同一个助手始终在工作台中可用。首次打开时关联当前页面；切换左侧一级工作台时自动恢复该工作台上次选中的对话，无历史则显示新对话；同工作台内切换页面仍保持当前对话。头部第一行显示助手图标、“AI 助手”和三个操作按钮；第二行将“选择历史对话”、会话选择器与当前工作区排在同一行；输入区上方直接显示本次协助对象和盘型，默认跟随当前编辑对象，也可固定对象。添加参考可选择其他博文或命例进行比较，参考资料只读。同一工作台沿用当前对话，跨工作台由导航自动恢复上次选中的对话或进入新对话。各条对话分别保留聊天与未发送的草稿。

- 高保真：[assistant-workspace.html](../design/mockups/assistant-workspace.html)。直接打开，或通过本地静态服务器访问。
- 默认场景：博客编辑，右侧 AI 助手展开。
- 左侧首页、博客、月亮图标可切换三个场景；下方评审条切换三款主题和窗口尺寸。
- 示例内容、命例、待办和 AI 回复均为合成演示。修改仅存在于本页内存中，刷新复原；不调用模型，不访问真实业务数据。
- 本稿只展示命理的八字场景，正式产品已有的紫微、占星能力保持原有范围。

原型阶段仅交付方案、可交互高保真与截图；正式实现现已接入应用外壳、对象会话及对应模块。原型中的合成回复仍只用于视觉对照。

## 2. 已确认方向与本稿具体取值

| 项目 | 方案 |
|---|---|
| 全局入口 | 顶栏保留 36px 单图标 AI 按钮，所有页面位置相同；填充图标与浅色底提示展开状态，悬停显示名称 |
| 展开方式 | 足够宽时右侧并排停靠；主内容仍可同时操作 |
| 常驻含义 | 助手与会话由应用外壳持有，页面切换不卸载运行任务；面板允许主动收起 |
| 展开偏好 | 正式应用记住展开状态和宽度；高保真稿刷新回到初始场景 |
| 何时联网 | 主动发送或点击明确的 AI 快捷指令时调用；导航、选对象、展开面板均不自动请求模型 |
| 当前对话 | 顶栏紧凑选择器按工作台查找对话，菜单贴着选择框底边展开，左边缘与选择框对齐；可用工作台即使没有历史也保留空分组，点空态才建立该工作台的通用对话，不切换页面。顶栏 ＋ 是常驻新对话入口，历史对话可重命名；删除图标原位变为“确认删除”，再次点击才删除。选择器仅显示真实会话标题，工作台名称保留在菜单中；标题单行省略，常态无填充底色；“选择历史对话”、选择器与当前工作区同排，长标题和工作区名称各自省略；悬浮信息图标或键盘聚焦时显示可读取范围与关联页面 |
| 上下文切换 | 同工作台切页保留当前对话；切换一级工作台自动恢复对应对话，若无历史则显示新对话，首次发送时创建。切换博客或命例时自动更新下一轮对象，不新建对话；输入区显示本轮对象并可固定，固定状态在本次运行中按对话保留。通用页面不会覆盖原有博客等业务对象 |
| 添加参考 | 输入区独立列出所选参考，可移除；弹窗以名称和更新时间或出生信息区分对象。最多选择 8 个同类参考，主对象不重复列入。AI 通过 `read_reference` 按所选 ID 读取，不能访问未选对象；写入建议仍只针对主对象 |
| 写入 | 沿用建议 → 确认 → 应用；原内容发生变化时重新核对 |
| 首版生成并发 | 同时一个生成任务，可跨页继续；另一会话可浏览和输入，发送暂不可用 |

正式应用采用 **380px 初始宽度、340–480px 可调整范围**。分隔条可拖动，也可聚焦后按左右方向键调整。

## 3. 空间分配

### 宽窗与默认窗口

顶栏沿用当前 54px 胶囊，左侧一级图标栏沿用 66px。主体为当前内容与 AI 两列，间隔 16px；两列分别滚动，助手标题、上下文与输入区固定在各自位置。

正式助手顶端与顶部胶囊下沿留 16px 间距，底端距窗口 12px；长对话在助手内部滚动，输入区固定在底部。消息区始终预留滚动条宽度，避免滚动条出现时让消息卡片重新换行。

输入框底部提供紧凑操作栏，右侧放模型选择和发送按钮，不另占一行面板空间。

展开和收起采用 220ms 的淡入淡出与轻微横移；宽窗口的主内容和二级目录占位同步收放，窄窗口仅面板过渡。减少动态效果设置下立即切换。

开启助手时，固定二级目录收起；悬停或键盘聚焦左侧工作台图标时，在图标旁展示对应工作台的二级目录。一级导航始终保留。博客笔记列表在空间足够时展示，内容区小于 650px 时改为编辑器顶栏的笔记选择器，保证正文宽度。

正文编辑表面沿用近白内层；大屏文字区最大宽度 900px。助手采用现有 `--ai-panel-bg` 实底，避免后景文字透入。保持深色主按钮、克制的雾蓝强调，沿用三主题、字体和 18 / 14 / 10 圆角体系。

### 最小窗口

本稿在工作台容器小于 **1160px** 时展示右侧覆盖抽屉，不继续压缩主内容。抽屉仍为非模态，保留左侧导航和顶栏入口；不盖全屏遮罩，不锁住整页，也不设置错误的模态焦点陷阱。

- 收起按钮、顶栏入口、Escape 都可收起，焦点回到入口。
- 点击正文不自动关闭，避免切换操作时反复丢失助手。
- 在覆盖模式点击“定位原文 / 日主”时主动收起面板，让被引用内容完整露出。
- 正式实现的停靠判定应看剩余主内容宽度与页面最低可用宽度；1160px 是本稿的初始验证值。
- 下方尺寸预设是评审工具，不属于正式产品；预览容器也会受宿主可用空间约束。

### 与素材浏览器的关系

当前素材浏览器方案也有博客右侧辅助区域。正式接入时将两者纳入同一辅助区域：用户明确切换“AI 助手 / 素材浏览器”，保留另一方的状态。AI 在浏览器可见期间仍可完成生成并给出状态提示，不并排叠加两条右栏。本稿展示 AI 一侧，未重做素材浏览器。

## 4. 会话与对象

“当前对话”采用紧凑的快速切换下拉：默认显示最近 4 条（当前对话不在其中时保留其入口），搜索覆盖全部会话，工作台筛选始终列出可用工作台；空工作台可在空态开始通用对话，不切换页面，也不自动读取博客或命例。顶栏 ＋ 是唯一常驻新对话入口；顶栏历史图标打开当前工作台的完整历史。下拉与历史均可重命名对话，删除操作原位变为“确认删除”，二次点击才删除且不能恢复，点别处或失焦取消。一个工作台允许多条对话；同一条对话可跨这个工作台的页面继续；同工作台切页保留对话和未发送输入，默认跟随新的编辑对象；仅在发送时读取对象的最新资料。切换一级工作台自动显示该工作台上次选中的对话，无历史则显示新对话。旧会话按其原始对象归入所属工作台，不合并消息。

“新对话”在当前选中的工作台和关联范围下创建。“选择历史对话”右侧显示当前工作区，悬浮或键盘聚焦信息图标显示详细范围；输入区上方直接显示本次协助对象和盘型，命例标明八字、紫微斗数或占星，可固定对象，取消固定后恢复跟随当前编辑对象；切换一级工作台时直接恢复该工作台对话，无历史则在首次发送时创建。若新页面只有通用帮助能力，例如图文发布，原来明确关联的博客仍是本轮业务对象；页面名称只作为导航上下文，不凭工作台归属扩大读取与写入权限。若新页面带有博客或命例对象，则改为本轮对象。

发送时以本轮对象重新读取最新内容，并校验其仍属于这条对话的工作台。Agent 提示词区分工作台、本轮业务对象、明确关联的页面和来自其他对象的历史消息；每条消息记录发送时的对象与页面。首页待办允许跨日延续；命理同一命例的三盘可共用对话并记录盘型；通用页面没有业务写入工具。页面上的 AI 快捷指令进入其工作台当前对话，并明确关联触发它的对象。

同一对话可以添加其他博文或命例作为只读参考。每轮只在提示词列出所选参考的 ID 和名称，内容由模型调用 `read_reference` 按需读取；未选对象和其他工作台的对象无法通过此工具读取。参考博客提供标题和正文前 10000 字；参考命例按自己的 ID 取盘面与最新笔记，盘型与主对象一致。发送记录保存本轮参考列表，打开对话时恢复最近一轮的选择；尚未发送的参考调整在本次运行中保留。参考已删除时明确报错，可移除后重发。主对象切成某份参考时，该对象自动从本轮参考中排除。写作快捷指令同样携带参考选择，但其写入目标仍是本次协助对象。

有待确认建议时切页或切换工作台，建议留在原会话。不同博客的建议分别保留，只有同一篇博客的新建议替代旧建议；应用按钮标明目标文章。导航不自动放弃建议，也不把它应用到新对象。

## 5. 三个场景

### 博客：一边看原文，一边推敲

助手显示文章名称。输入区上方的写作快捷指令作用于正在协助的文章和当前对话；每轮自动提供关联文章的标题及正文前 10000 字，编辑器不再放置常驻选区引用按钮。旧对话中的引用来源仍可点击定位。建议卡明确区分原文和新文，先展示新版本，可展开原文核对。

“应用到正文”使用本次建议绑定的文章和版本。成功后卡片显示“已应用”，正文同步更新；可可靠还原时提供撤销。若应用后用户又编辑过正文，撤销不得覆盖这些新修改。本稿包含版本变化拦截与撤销保护演示。

本稿引用与修改限定为开头段落，任意选区映射属于正式接入工作，不以演示冒充完整富文本编辑能力。

### 首页：把变更说清楚

示例“把阅读安排到明晚八点”对应一张待办变更卡，展示事项标题、原时间与新时间。点击确认后更新示例待办；暂不调整保留原内容。正式接入复用现有待办建议工具与事务校验，不新增上游没有的待办字段或功能。

### 命理：解读与盘面互相对应

助手显示当前命例及盘型。命理内容以只读解释为主，示例从日主和五行分布开始；“在盘面中定位日主”对应实际可见的日柱。切换命例保留同一对话，下一轮跟随当前命例和盘型。AI 解读按钮只发送短问题和对象标识；后端按命例 ID 提供最新盘面及笔记，八字补齐藏干、纳音、神煞、起运、当前大运和流年。仍由命例 ID 管理各自笔记。

算法仍由现有命理模块负责，模型接收已经算好的结构化盘面，避免在聊天层重新推算并与页面产生两个结果。

## 6. 任务生命周期与恢复

| 操作 / 状态 | 用户可见行为 |
|---|---|
| 发送 | 输入进入当前会话，展示生成状态与停止按钮；面板以正常聊天方式定位最新内容 |
| 生成时切页 | 页面正常切换，原任务继续；顶栏显示原对象与“生成中”，点击可返回 |
| 在新页面输入 | 同工作台保留当前对话和输入，下一轮对象可随页面改变；已有任务运行时发送不可用，并解释原因 |
| 后台完成 | 结果写回原会话，顶栏显示原对象与“已完成”，不强制打开面板或抢焦点 |
| 收起 | 保留输入、消息、建议和运行任务；打开后继续原状态 |
| 停止 | 中止生成、保留已收到内容与可重发输入；不会应用半成品建议 |
| 请求失败 | 保留问题及已有内容，原位给出重试；不清空整段对话 |
| 应用建议失败 | 保持待确认或冲突状态；成功后才显示已应用 |
| 目标已删除 | 标记原对象已不存在，历史可读，禁用写入，不能改绑到当前的新对象 |
| 应用退出 | 正式接入后恢复历史，未完成任务标记中断并允许重发，不假装继续生成 |

每次请求固定会话、模块、对象、盘型 / 选区和本轮内容版本。回包按请求绑定归位，不再查“此刻页面在哪”。

首版只保留一个生成槽位，降低从现有单 `activeRequest` 实现演进的复杂度。页面能自由切换，与多会话并发执行是两件独立的能力。

## 7. 正式接入的最小改造边界

实施基线：`src/App.tsx` 持有全局 `AiPanel`、页面上下文和后台状态；`electron/ai-ipc.ts` 维护单个运行请求与按会话保存的待确认操作。

| 层 | 调整内容 |
|---|---|
| 应用外壳 | 统一停靠 / 覆盖布局；持有展开、宽度、页面上下文和后台任务提示 |
| 页面接入 | 首页、博客、命理分别上报业务对象；选区和盘型属于本轮上下文 |
| 会话 | 按工作台管理对话，逐轮记录业务对象、页面、盘型和参考列表；已有无 module 历史仍按原待办逻辑兼容 |
| AI 内核 | 沿用模块贡献机制；根据会话所属模块装配上下文与工具，命理只读能力单独注册 |
| 请求与建议 | 将运行状态和待确认建议关联到会话与对象；切页不清除其他对象建议；写入时重检目标版本 |
| 业务存储 | 待办仍走现有共享 tasks/categories；AI 配置与聊天仍为工作台独立存储；文章与命例仍由各自模块管理 |

现已按上述边界接入，正式运行合同同步记录在 `DESIGN.md` / `UX-CONTRACT.md`。素材浏览器目前仍是独立页面，由通用助手回答页面问题；尚无嵌入博客编辑区的第二条辅助栏。

## 8. 评审与验证

评审重点：380px 对话阅读是否舒适；目录和笔记列表收起后是否好找；对象名称是否足够醒目；窄窗覆盖是否可接受；建议卡是否能让人放心确认。

本稿应验证：

1. 三个页面的上下文、记录与未发送输入分别恢复。
2. 博客与待办的确认 / 保留 / 撤销，正文改动后的冲突提示。
3. 生成时切页、后台完成后返回、停止生成。
4. 同对象新对话与历史恢复，不同命例与文章不串话。
5. 三主题、1280×820 与 1024×680、收起后扩展主内容、分隔条键盘调整。
6. 核心文字与操作不发生横向溢出；长聊天内部滚动，输入框和收起入口可达。

原型的实际检查结果与截图在 [AI-ASSISTANT-PREVIEW-QA.md](AI-ASSISTANT-PREVIEW-QA.md) 中记录。正式应用另以类型检查、构建、测试和启动冒烟验证；真实模型输出仍取决于用户配置的供应商与模型。
