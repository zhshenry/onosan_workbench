## 入口和布局

左侧一级“游戏工作台”或首页同名入口进入轨迹侦探，二级目录显示当前项目“轨迹侦探”；沿用共享导航规则，助手展开时固定目录收起，可通过工作台图标浮层访问。项目栏、左侧游戏预览和右侧测试检查共用一个工作区，终端仍位于项目底部；窄窗可将测试栏收起/作为前景面板打开。游戏源码和真实网页界面保持原样。

顶部项目栏采用方案 1：名称旁显示服务状态，主按钮启动/重启，运行后可停止；「终端」「检查」用选中态表示展开。右侧「⋯」收纳打开项目目录、项目运行说明与项目设置，设置仍需先停止服务和测试。完整项目路径保留在副标题提示中，小窗口自动换行。

初始项目 `C:\Myself\Personal_Game\Trail-Detective`，网页目录 `ui-preview`，端口 `8765`，入口 `/index.html`。停止服务和测试后，可在项目设置中调整目录、端口或 Playwright 模块位置。设置和结果在 Ono 自己的 `userData/games/trail-detective` 中保存。

## 项目运行说明

未启动时点击「查看项目运行说明」，或随时从项目「⋯ → 项目运行说明」进入 Ono 内的只读弹窗。默认读取当前项目 `README.md`，正文支持标题、列表、代码和表格。点击项目内 Markdown 相对链接继续阅读，支持章节跳转；使用「上一篇」返回，使用「运行说明」回到 README。关闭按钮或 Escape 返回当前试玩，保留游戏页面和试玩档。

读取无需启动服务，不修改文档；仅允许项目内 1 MiB 以内的 `.md`/`.markdown`，符号链接也不能指向项目外。文档中的 HTTP(S) 链接在系统浏览器打开；嵌入脚本、图片与其他协议不执行或载入。文件缺失等读取错误在弹窗内显示，可重试或返回。

## 运行与试玩

- 本地静态服务仅绑定 `127.0.0.1`，不缓存响应；路径及符号链接均限制在网页根目录中。
- 端口冲突时说明原因，可修改端口，或由用户核对后连接已有服务。外部服务只断开，不终止其进程。
- 跟随窗口、桌面 1440×1000、窄屏 390×844 作为真实 CSS 视口，固定视口按比例放进预览区域。
- 预览工具栏右侧「⋯」更多功能提供与浏览器一致的 25%–500% 网页缩放、当前百分比和恢复 100%，并收纳试玩存档选择、截图与外部打开。菜单可用方向键浏览，Escape 关闭后焦点回到入口。缩放仅改变游戏页面，不重载试玩；100% 时预览尺寸对应上述 CSS 视口，其他比例沿用浏览器缩放对 CSS 可视范围的调整，切换预览尺寸和普通切页保留比例，新档分区独立。
- 保留试玩档使用专属持久分区，新档试玩使用内存分区；均不共享通用浏览器分区或自动化测试档案。
- 重置保留档：切换到目标环境并选择「保留试玩档」，从预览工具栏「⋯ → 重置保留试玩档…」打开确认框，核对环境和站点后点击「确认重置」。会清空该站点在此设备的进度及网页设置（localStorage/IndexedDB），并重新载入当前试玩；本地服务未启动时，下次启动从头开始。取消、关闭或 Escape 保留数据。另一环境、临时档、通用浏览器、旧站点数据及项目文件不受影响，Cookie 和服务器端存档不清理。临时新档可继续通过「新档试玩」重新创建，无需重置保留档。
- 普通切页保留同一宿主与 guest。刷新由用户主动执行，保留相应试玩存档。
- 本地代码变化后，预览地址栏左侧的刷新图标变为琥珀色「刷新试玩 · 有更新」，不再显示独立的整行提醒。点击刷新当前试玩页面后恢复普通图标；右侧旧测试结果仍显示待重测，需另行运行检查。线上不显示本地源码更新提示。
- 截图在主进程中采集当前游戏租约，只能打开该工作台记录中的 PNG 附件。

## 线上试玩

预览标题下切换「本地开发 / 线上试玩」。两个真实浏览器独立保留本次会话的页面、历史、视口和缩放；线上不依赖本地服务。没有默认示例域名，首次从「设置线上地址」进入共享弹窗，填写 HTTP(S) 完整地址并保存，可使用子目录、页面、查询与片段。线上地址可在本地服务或测试运行时独立修改，正常重启后恢复配置。留空取消配置，不删除旧站点存档。

线上保留档使用 `game-trail-online` 持久分区，临时新档沿用 `game-trail-fresh-online-*` 内存分区；均与原本地、通用浏览器和自动测试隔离。原本地分区名称保持原样。网址更换后浏览器按站点隔离的旧数据保留，页面返回配置的新入口。游戏工作台普通切换保留浏览器实例，应用重启只恢复持久存档。

侧栏常驻地址编辑/复制、试玩档切换、新档、实际截图、问题描述与报告复制。问题草稿和本次截图引用按线上地址及试玩档分别保留在本次会话，持久截图附件仍在 Ono 自有目录；复制不自动发送内容。线上截图由主进程验证拥有的线上标签、分区及当前配置站点，截图时导航或换地址会拒绝该次记录。

「线上检查」默认折叠，仅检查配置地址的真实 HTTP 访问，最多跟随五次 HTTP(S) 重定向、八秒超时；报告真实状态码和时间。本地五项源码检查与独立 Edge 通关仍从「本地开发」执行，不冒充线上通过。「版本与诊断」展示真实载入状态、当前页面、缩放及外部打开；尚未接入发布版本信息，界面明确标注。没有新增部署、回滚或远程终端。

测试展示采用用户选定的[下拉切换方案](../test-selector/README.md)：快速检查用共享 Select 选择五项，显示实际状态与待重测提示；下面展示该脚本的检查内容、检查方式、真实结果和按需展开的输出。切换不自动执行，重跑只运行选中项；完整通关直接展示唯一任务。运行操作固定在栏底，正文单独滚动。

## 项目终端（终端方案 2）

顶部“终端”展开全宽底部面板，首次打开才以当前游戏目录启动真实 Windows PowerShell。实现为 xterm.js + FitAddon 渲染、node-pty/ConPTY 承载会话，依赖作为应用运行依赖保留；主进程构建不内联 node-pty，首次打开才加载原生模块。没有内置代码编辑器或新增 AI 命令工具。

- 可以输入/粘贴命令、显示中文与 ANSI 输出；Ctrl+C 或中断图标停止当前命令，保留 PowerShell。结束会话终止该 shell 与拥有的子进程，可重新连接新会话。
- 默认收起，展开高 240px；分隔线拖动或方向键/Home/End 可调高，窄窗按可用高度夹紧。终端在预览与检查共同下方，不替换右侧检查。
- 收起和工作台切换保留同一个 PID、变量和显示缓冲；普通后台状态更新不抢回键盘焦点。应用退出清理会话，下一次打开从新会话开始。
- 会话绑定创建时游戏目录；活动会话期间更换项目目录会得到明确错误，避免把后续命令误送到旧项目。项目标签展示初始目录，用户在 shell 中自行 `cd` 后由真实提示符表达当前目录。
- 所有终端 IPC 只允许主窗口主文档，输入与尺寸校验会话 ID；单次输入上限 64KB，初始重连缓冲上限 50 万字符，仅保留在内存。PowerShell 自身命令历史遵循系统默认行为。
- 清空同时同步 xterm 和 Windows PTY；复制选区或最近缓冲，超过 19000 字符只复制尾部并提示。启动失败保留错误与重连入口。

预览仍是实际视口。展开终端会减小网页可用高度，游戏自身的高度响应式表现会直接显示；可用既有桌面/窄屏固定视口或收起终端检查完整画面，不修改游戏 CSS 来美化测试结果。

终端依赖参考：[node-pty 官方 Electron 示例](https://github.com/microsoft/node-pty/blob/main/examples/electron/README.md)、[xterm.js FitAddon 用法](https://xtermjs.org/docs/guides/using-addons/)。

## 状态与恢复

未运行、等待中、运行中、通过、失败、已取消、未执行均有文字。快速检查失败后继续执行其他独立检查；单项可重跑。取消终止此次拥有的进程树，尚未执行项回到未运行；不结束按端口搜索到的其他进程。

测试开始前和结束后读取源码指纹，文件监听更新当前指纹。已运行结果的指纹与当前不同则显示待重测；测试期间修改源码也适用。进程退出码决定结果，原始输出保留；缺失脚本、Playwright、Edge 或服务未就绪显示未执行。完整通关只报告实际脚本的任务状态，不伪造步骤级进度。

问题报告包含运行时项目目录、任务与脚本、测试服务、当前试玩页、所选视口、错误输出、附件和手工补充的复现步骤。明确点击复制才写入剪贴板。当前附件为脚本实际生成的检查点或手动截图，不冒充失败瞬间截图。

### 保存问题反馈（方案 2）

在「测试检查」标题旁点击「记录问题」打开右侧抽屉；线上试玩在「问题记录」栏目使用同名按钮。没有失败测试或本地服务时也可以填写。分别记录标题、复现步骤、期望表现和实际表现，可勾选已有截图或截取当前试玩页（最多 6 张）；截图可以点击打开查看。选择附带当前测试结果和服务日志，点击「提交并保存」将它们冻结为独立问题包。保存失败保留草稿；关闭未保存内容会确认是否放弃。

普通运行实例的默认目录为：

```text
C:\Users\henry\AppData\Roaming\OnoWorkbench\games\trail-detective\issues\TD-YYYYMMDD-xxxxxxxx\
  issue.json          问题描述、环境、检查快照与附件清单
  report.md           可阅读的完整问题报告
  screenshots\*.png  已勾选截图的独立副本（可选）
  test-output.txt     当前所选测试的原始输出（勾选时）
  service-log.txt     提交时的服务日志快照（勾选时）
```

`xxxxxxxx` 为随机编号，避免并发覆盖。实际保存目录在抽屉底部完整显示，提供「打开文件夹」「复制路径」。「导出 ZIP」另开系统保存对话框选择导出位置，打包上述实际文件，不仅仅是原截图路径。独立测试实例使用自己的 userData 路径，以界面显示为准。

「已保存的问题」可读取最近 50 条记录，关闭并重启 Ono 后仍可打开。原截图被替换或重新测试不会改写已归档副本。线上问题保存独立的页面、站点和 HTTP 访问检查，不能附带本地测试/本地日志，也不声称收集服务器日志。这里的「提交」仅保存本机，未连接外部问题平台；未提交草稿和线上侧栏快捷备注仍不会在重启后恢复。

## 验收

单元测试：`node --import tsx --test tests/game-workbench.test.ts`。覆盖只读 HTTP 根目录、端口冲突、外部服务断开、固定脚本/退出码、继续执行、并发拒绝、取消、指纹过期与附件范围。

问题包测试：`node --import tsx --test tests/game-issues.test.ts`，覆盖独立副本、重启读取、ZIP 内容、输入与路径校验、环境隔离和并发独立记录。原生界面验收：设置绝对路径 `GAME_ISSUES_QA_DIR` 后运行 `node tooling/game-issues-pilot.mjs`，使用独立 appData 与游戏副本核对填写/失败重试/重复提交/截图/系统文件操作、退出重启及三主题双尺寸。

界面验收使用隔离 appData、独立试玩分区和项目副本中的模拟失败，不修改真实游戏源码、用户现有 Ono 数据或浏览器玩家存档。核对真实游戏的五项检查、独立 Edge 通关、刷新和跨页保留、新档隔离、真实窄屏视口、截图、三主题及 1024×680。
