# 游戏测试检查 · 下拉选择

2026-10-19，用户选定方案三。

![已选方案](design/game-check-select-option-3-2026-10-19.png)

五项快速检查收进「当前检查」下拉选择器，选择与执行分开。名称与当前状态在触发器、选项中同时显示；没有记录时显示未运行，代码变化后的旧结果显示待重测，并汇总待重测数量。完整通关只有一个任务，直接展示详情。

详情按检查什么、怎么检查、上次结果、原始输出排列。说明依据现有固定脚本，不新增测试或细分通过数；模拟页面检查与真实 Edge 通关明确区分。结果、耗时、输出、附件仍来自真实进程。首次未运行和运行中的文案分别说明状态，失败自动展开原始输出。

结果摘要采用紧凑两行：首行显示上次结果、状态、月/日时分和耗时，次行显示过期提示。完整日期时间保留在悬停提示与 `time` 的日期属性中；失败原因单独保留。

复用 `src/ui/controls.tsx` 的 Select/Segmented，侧栏以 `src/views/game.css` 和既有三主题 token 呈现。下拉选项与触发器等宽，使用共享 portal、方向键、Home/End、Enter/Space、Escape、外部点击和窗口避让。选择后焦点返回触发器；弹层不推移详情。按钮保持约 34px 高度，固定在侧栏底部；详情及附件独立滚动，原有截图、问题反馈和服务日志保持可达。

实现范围：`src/views/GameView.tsx`、`src/views/game.css`；原问题反馈验收的检查列表定位同步为选择器定位。真实游戏源码与测试逻辑不变。
