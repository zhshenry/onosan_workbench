# Bot 长期记忆技术规格

## OnoSan 长期记忆方案

记忆逐条存入 OnoSan 的 `chats.db`。私人记忆归当前 Bot，全局记忆在本产品实例内共享。正文保存在 `bot_memories`，来源身份、审查状态及开关周期由 `bot_memory_inputs` 记录。

1. **先限定读取范围，再套用预算。** 用户直接与 Bot 对话时，该 Bot 可用自己的私人记忆和全局记忆。Bot 间只读询问只可用全局记忆与用户明确授权的资料。Host 根据请求来源定范围，现有 Bot Runtime 的常用注入和按需检索工具 `search_memory` 共用这套规则。私人记忆在组装只读询问的提示词时即被排除。
2. **按真实用户发言触发审查。** 模型处理完当前回合后，Host 将实际送入本轮的用户消息 ID 加入持久审查队列。排队编辑取执行时的正文，排队删除移除来源，引导现有任务沿用原消息 ID。工作区自动填入的模板、Bot 回信、审批和重试本身均不新增来源。已停止、超时或被新一轮替代的结果丢弃。记忆写入与审查进度一并提交。后台提炼只处理当前 Bot 的私人记忆，遇到同义结论可加新证据，用户明示纠正时可修订同范围的自动记录。全局记忆由用户在聊天里明确授权或在记忆页选择。
3. **自动记忆由 Host 控制。** 设置新增「记忆管理」，只有一个「是否开启自动记忆」开关，默认关闭，对实例内各 Bot 生效。Host 在排队时核对开关，提交时核对开关和候选是否属于当前这次开启。关闭后丢弃尚未写入的候选，再开启只处理之后的新发言。用户可主动通过对话保存，也可查看已保存条目。

长期称呼的新增和更正由当前 Agent 调用 `remember`，写入成功后在对话里确认。普通聊天中，Agent 仅在用户本轮明确要求长期保存、更正或继续保存时调用 `remember`。查询记忆、核对保存结果及追问工具行为属于只读。普通聊天写入时 Host 核对用户原话和共享授权。聊天明确表示仅当前 Bot 使用或拒绝共享时，只允许私人写入。删除私人记忆会作废该 Bot 删除前尚未完成的自动审查。切换工作时，前台记住和后台审查共用原消息 ID，并使用实际转交给模型的新请求正文，包括多行内容。

Agent 用 `remember` 的 `replaceId` 更正已有记忆，原 ID 保留并关联这次原话。Host 核对本轮已读版本和授权范围。

常用区超额时，按同范围内的最后正文修改或明确记住时间，从旧到新移出条目。退出常用区的条目保留正文、ID 和来源，仍可按需查询。主动保存进入所属范围的常用区，后台提炼默认按需。每轮私人常用最多 10 条且不超过 1,000 字符，全局常用最多 5 条且不超过 500 字符，按需整轮最多新增 5 条且不超过 900 字符。每条新记忆最多 300 字符，原有长条保留原文，可从列表打开全文，模型按需读取相关片段。

一个条目可关联多个支持当前结论的用户原话。打开原文时按各自会话权限校验。记忆页沿用现有资料页入口，参照资料库展示可点击的单行列表，提供「全部」「当前 Bot」「全局」三个筛选。每条显示小标题和一个主题标签。详情在完整正文上方显示标题与标签。标题行右侧可展开原话，原话统一显示在正文下方的带边框区域。空状态沿用已确认的样式。

标题、主题和正文独立保存。标题最多 32 字，主题最多 16 字。Agent 主动保存及后台自动提炼可以生成标题和主题。空缺字段按正文补显示，称呼条目显示「称呼偏好」和「称呼」，其他条目取正文开头作标题，主题默认「未分类」。旧记录读取时兼容缺失字段。

长期记忆清单只统计当前记忆库中的独立条目。用户询问当前保存了哪些记忆、共有多少条或某条是否还在时，Agent 必须先调用 `list_memories`，以本轮结果为准。它读取与记忆页同源的数据库记录，包含当前授权范围内的常用和按需条目，返回总数、匹配条目和分页位置。查询失败时由 Agent 说明本轮无法核对。`search_memory` 用于补查当轮尚未读过的相关条目。

## 对话式新增记忆

手动新增和编辑统一通过目标 Bot 的对话完成。用户从记忆页发起，或在日常聊天中直接提出要求，都由当前 Agent 调用 `remember`。点条目详情里的「编辑」可回到原对话说明要修改的内容，Host 固定所选条目的 ID、版本和范围。修改正文、标题或主题时保留用户未要求修改的部分。排队期间条目有变化时提示重新打开详情。删除在详情中确认。自动记忆开关控制后台从日常发言提炼记忆，用户主动发送的保存请求可独立执行。

### 用户怎么用

1. 在记忆页点「＋ 添加记忆」后回到该 Bot 的已有对话，焦点落在输入框。输入区显示「添加记忆 · 当前 Bot」，也能明确选择「全局」。记忆列表的范围筛选用于浏览，聊天输入区的选择用于授权这次保存。
2. 用户输入想记的内容并发送。已有普通聊天草稿单独保留。正在执行工作时，这次新增作为独立消息进入该 Bot 的现有队列。内容和范围明确时，发送即授权处理。若指代或范围有歧义，Agent 在同一会话追问，并将澄清关联到这次记忆请求。
3. 写入成功后，在原回复下显示带范围和标题的简短回执，点「查看记忆」定位到该条目。完成后恢复普通输入。取消时回到原草稿。模型或保存失败时显示当前状态，保留请求供重试。

保存请求沿用该 Bot 的原模型会话。聊天历史用于理解用户所指的内容，本轮提示提供所选范围从数据库读取的记忆总数和常用条目。内容和范围清楚时，即使同义记录看起来已经存在，也由 `remember` 核对当前库并取得新增、更新或复用的回执。模型正常结束且无保存回执时，在原回复下显示「本次未保存到长期记忆」，用户可以继续补充。

例如同一个 Bot 已记了「周报先写进度」。在记忆页点添加后发「以后周报先列风险，再写进度」，Bot 回「已更新当前 Bot 的『周报顺序』」，回执下可点「查看记忆」。列表上还是这条「周报顺序」和「写作」标签，详情与来源更新为这次的新约定。

### Agent 和后台怎么处理

- 页面入口给这次真实用户消息带上保存意图与所选范围。普通聊天的 Agent 根据消息含义识别主动保存。标题和主题由 Agent 生成。称呼新增和纠正也进入同一个 Agent 工具流程。 [Bot 对话面板](../../../../../src/views/BotPanel.tsx) · [记忆工具](../../../../../electron/bot-runtime.ts)
- `remember` 提交前，由 Host 在目标范围内按标题、主题和正文批量取候选，覆盖常用和按需条目。条目少时可以一次提供该范围的全部旧条目，较多时提供可能相关的一批。Agent 一次对照这批内容。有新信息就新增，同义就复用已有条目并关联有效原话，明确改口就用原 ID 更新。多条候选都可能符合时先请用户指明。 [DS Bot 面板的批量对照源码](https://github.com/Fei2411/DS-Bot/blob/v0.3.9/ds-bot/src/host/memory.js#L1380-L1413)
- 「添加记忆」中的 `remember` 由 Agent 提交记忆内容，Host 从同一次保存请求读取原消息和澄清消息，保存消息 ID 和原话片段。用户确认时可说「就存刚才那条」。来源自动关联参考 DS Bot。 [DS Bot 来源关联源码](https://github.com/Fei2411/DS-Bot/blob/main/ds-bot/src/host/memory.js#L998-L1026)
- Host 按真实用户消息核对来源、范围和旧条目版本，再提交到 SQLite。同一个请求的重试复用已提交的结果。全局写入需要输入区的明确选择或经核对的用户原话，授权冲突时先澄清。详情页保存接口只更新已有记录。回执来自实际提交，后台自动审查按消息 ID 跳过已完成主动保存的原话。 [记忆存储](../../../../../electron/bot-store.ts) · [详情保存接口](../../../../../electron/bot-service.ts)

### 参考来源

- **私人／全局范围**参考 [Grok Bot 的产品说明](https://docs.x.ai/grok-bot/bots#what-a-bot-remembers)。Bot 间只读权限和开关生效规则由 OnoSan 定义。
- **回合后增量审查、按需检索和代码腾位**参考 DS Bot 的[审查触发](https://github.com/Fei2411/DS-Bot/blob/v0.3.8/ds-bot/src/host/memory-review.js#L371-L397)、[检索工具](https://github.com/Fei2411/DS-Bot/blob/v0.3.8/ds-bot/src/host/memory.js#L1151-L1212)和[主记忆溢出处理](https://github.com/Fei2411/DS-Bot/blob/v0.3.8/ds-bot/src/host/memory.js#L461-L484)。OnoSan 用真实用户消息 ID 去重。
- **常用记忆的有限预算和有依据的抽取**参考 [Hermes 的容量规则](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory#how-it-works)和[审查提示词](https://github.com/NousResearch/hermes-agent/blob/v0.23.2/agent/background_review.py#L443-L472)。方案中的预算数值由 OnoSan 设定。
- **多条原话对应一个结论**按用户要求纳入，对照 [OpenClaw 的多来源追踪](https://docs.openclaw.ai/concepts/memory-provenance)。

验收时分别验证用户对话和 Bot 只读询问的可见范围。补充、审批、回信与重试同一任务时，只有新用户发言进入审查。审查进行中关闭再开启，确认旧候选无法提交，开启后的新发言可正常记录。
