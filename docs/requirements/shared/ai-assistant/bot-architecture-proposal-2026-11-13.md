# OnO Bot 工作台接入方案

日期：2026-11-13。更新：2026-11-18。状态：OnO M0–M5 已实现于当前工作区，包含独立本地 Host；原阶段证据见[实施与验证记录](bot-implementation-validation-2026-11-16.md)，后续协作核心及最新界面、性能与历史管理路线统一见[完整改造方案](bot-collaboration-and-sync-plan-2026-11-17.md)。通用契约见[通用架构](bot-workbench-architecture.md)；本文维护业务映射及原迁移记录。CMO 已独立迁移核心，实际状态和剩余工作见[CMO 方案](../../../design/cmo-bot-workbench-implementation-2026-11-15.md)。本轮仅更新文档，不新增运行实现或发布。

当前已实现行为参照 [DESIGN.md](../../../../DESIGN.md) 和 [UX-CONTRACT.md](../../../../UX-CONTRACT.md)；既有 [spec.md](spec.md) 的业务工具和人工确认规则继续适用。新增长对话管理仅写入完整方案 P6，不因本文更新变为已实现功能。

## 1 OnO 产品范围

OnO 接入通用 Bot Host 和 Pi 执行层，使用自己的模型配置、凭据、数据目录和业务工具；无需云端电脑。左侧工作台目录改为 Bot 联系人，现有业务页面进入各 Bot 的工作区。

| 项目 | OnO 接入要求 |
| --- | --- |
| 首页 | 后续重构为总台，承载总 Bot 主入口及跨工作台概况；完整首页单独设计 |
| 待办与日程 | 独立工作台及领域 Bot，保留既有共享库和上游同步约束 |
| 设置 | 保留人工设置弹窗，不创建设置 Bot、上下文或操作工具 |
| 助手 | 并排／浮动两模式，首次选择、记住上次、随时切换 |
| 后台运行 | 独立本地 Host；通用设置可开启 Windows 系统托管，UI 退出后仍运行。默认关闭时随 UI 正常退出停止；设备休眠或关机期间不能执行 |
| 业务页面 | 保留实际编辑、发布、项目、测试、浏览器和小工具页面 |
| 灵动岛 AI 对话 | 固定直达 OnO 总 Bot，与总台共用同一主对话和任务状态；不跟随主窗口领域切换 |
| 外围通知 | 灵动岛消息、提醒和任务通知保留来源、未读及原负责人定位 |

设置仍可人工配置供应商、模型和密钥。显示模式只管理界面，Bot 资料和记忆从 Bot 自身入口管理。

## 2 Bot 和工作区映射

首期七 Bot 已在 2026-11-17 拆分为下表八个默认 Bot：命理沿用原工具助理身份，阅读新增独立身份，签到归总台。迁移首次生成 UUID `botId`，固定 `seedKey` 唯一且重复迁移不重建；用户改过的名字保留，不能用默认名称覆盖。

| seedKey | 默认名字／业务标签 | 目标 workspaceId → 原页面 viewId | 负责范围 |
| --- | --- | --- | --- |
| `coordinator` | Ono／总 Bot · 总台 | `home` → `home`、`checkin` | 跨领域请求、任务概况、待判断事项、Bot 名录与签到状态 |
| `schedule` | 小历／待办与日程 | `todo` → `todo` | 日历、待办与日程资源，保持原共享数据及同步 |
| `media` | 小墨／自媒体 | `media` → `copy`、`copy-publish`、`media-browser` | 博客编辑、图文发布、我的小红书，按所选稿件读取 |
| `game` | 游伴／游戏 | `game` → `game` | 游戏页面及明确关联的项目，能力以实际工具为准 |
| `web` | 小舟／网页与网站 | `web` → `browser`、`hush-hour`、`personal-website` | 网页和网站，各项目及浏览器资源分别关联 |
| `ai-test` | 小测／AI 测试 | `ai-test` → `ai-test`、`ai-test-tasks`、`ai-test-history` | 对比测试、测试任务与运行记录 |
| `utilities` | 命理助理／命理 | `bazi` → `bazi` | 命例、排盘与解读，沿用原工具助理稳定身份 |
| `reading` | 阅读助理／阅读清单 | `reading` → `reading` | 书目、阅读进度与读书笔记，独立主对话 |
| 无 | 设置／无 Bot | `settings` → 现有 `settings-*` | 人工配置，不成为可执行领域 |

原“小工具”聚合入口已拆分；每日签到通过总台卡片进入完整记录，应用连接／账号及自动签到配置在设置，未连接状态定位对应设置，不增加签到 Bot。其他子目录继续作为工作区模块，同类项目作为独立对象，不合并业务数据库。CMO 保持自己的六领域，不复制此映射。

领域主对话不默认读取全部命例、阅读档案或账号。旧混合主对话、草稿和任务保留，书目专属历史按拆分迁移归阅读；用户明确选择对象后才能读取，新增身份不自动扩展账号操作能力。浏览器仍按实际任务、站点和标签授权。

旧高保真的联系人只是示例数据；按真实名录渲染八个默认 Bot。联系人区域可滚动，设置保持固定，展开／折叠同步紧凑化并保留已确认悬停外框；动态创建用户 Bot 继续留作后续。

## 3 OnO 双模式界面

沿用此前已选定的并排和浮动交互，按 [2026-11-15 外观优化方案](../../../design/appearance-system-proposal-2026-11-15.md)修订高保真。两种模式共享同一 Bot、主对话、任务、草稿、焦点和回复目标；浮动模式起始或收起输入框时保留底部胶囊，选择“收起助手”后完全隐藏助手，通过顶栏重新展开。跨窗口输入遵循通用方案第 10.7 节的分入口草稿契约，当前运行协议为 v7；名片、编辑弹窗、交付件和浮动异常状态遵循第 10.8 节。11-16 的[六个主要状态稿](design/bot-state-review-2026-11-16.md)已获确认并据此实现；后续冲突按完整方案第 5.5 节修订，原验证范围见实施记录。

已确认的并排布局及 v3 入口稿采用「悬浮导航 + 强玻璃 + 窗影·午后」。本轮补充经典、悬浮两套导航对照，两张均保持助手并排、强玻璃与窗影午后；不是在两种导航之间只保留一套。v3 将业务资料改为交付件并移到对话顶部；浮动助手两图保留为上一轮交互参考，身份入口与顶部布局同样遵循下方更新规则。图片记录设计选择，当前实现与运行验证以实施记录为准；新安装和升级默认值仍按外观方案处理。

确认记录（2026-11-15）：用户针对并排 v2 回复「没问题」。确认范围为移除独立 Bot 身份行、对话与工作区上移后的空间比例，以及 Bot 信息、模式、任务和业务资料的入口归属。当时尚待细化的名片、编辑弹窗和浮动布局已于 11-16 确认并实现，运行证据单独记录。

追加调整（2026-11-15）：用户要求将「业务资料」改为「交付件」，并作为按钮放在对话面板顶部。该入口的名称、内容及位置以当前 v3 和下方规则为准。

| 模式 | OnO 采用的方式 |
| --- | --- |
| 并排 | 左侧 Bot，中间持续主对话，右侧原生工作区；工作区可独立收起，对话可展开为主区域 |
| 浮动 | 工作区优先，底部胶囊展开输入，当前答复浮在上方；可打开同一主对话的完整记录 |

11-16 追加：浮动交互采用 metadata-analysis 的「300×44px 流光胶囊 → 紧凑输入框」及一次顶栏下全局光波，输入样式沿用 OnO。当前／最近一轮答复单独浮在上方，正常最高 240px，真实流式输出、长文内部滚动，思考与工具默认收起；待回答和待确认卡允许增高，旧的未决操作保留。更多菜单“完整对话”恢复并排中的同一主对话。收起显示不停止工作，停止回复仍通过原任务取消执行。具体尺寸、动效降级与临时画面边界以根目录 DESIGN.md / UX-CONTRACT.md 为准；参考项目当前 JSON 返回并不代表 OnO 使用模拟流式。

11-17 追加确认：用户选中[资料 / 记忆 / 定时任务三页签稿](design/bot-profile-tabs-selected-2026-11-17.png)。三个页面都保留在联系人旁的同一资料面板内，定时任务不再触发工作台跳转；顶部身份与右上编辑／关闭固定，列表与表单在内容区切换。记忆、计划创建、启停和版本校验继续复用真实接口，表单跨页签保留，未保存关闭先确认；具体几何与键盘规范由根目录 DESIGN.md / UX-CONTRACT.md 维护。

### 3.1 外观适配规则

1. 经典沿用当前应用的整条横向长胶囊顶栏，四周留出背景间距，全部控件位于同一圆角外壳内；悬浮使用四组独立表面：紧凑 Logo 与导航开关、日程待办、工具与头像、系统窗口按钮。两种样式共用控件位置，左上不显示应用名称；保留原按钮、动态避让和拖动规则。
2. 左侧导航统一改为 Bot 联系人，头像、名字和职责标签共同识别负责人。经典使用接近全高的纵向长胶囊，与顶栏及窗口边缘留间距、外壳互不相连，联系人从顶部排列、设置固定于胶囊底部；悬浮为顶栏与独立左下设置之间垂直居中的较短导航胶囊。两种导航共用展开/收起占位，不改变主内容坐标；原子目录进入所选 Bot 工作区，不把旧导航树再复制进联系人列表。
3. 主区域移除独立 Bot 头像、名字、职责及操作条，对话与工作区的顶边对齐到全局顶栏下方，保留必要间距；回收的高度用于正文和消息。Bot 身份由左侧联系人承担，联系人行用于切换工作台，旁边独立的信息按钮用于打开 Bot 名片，两个点击目标不混用。业务页面自己的标题卡保留，经典、悬浮一致；已在工作区外壳内的标题共享该外壳，不能把“移除 Bot 身份行”实施为删除业务标题卡。
4. 对话面板已有标题行左侧保留「对话」，右侧放「工作进度」「交付件」及收起按钮，工作区标题行移除原「资料」入口。11-16 用户追加调整：模式切换集中到全局顶栏 AI 助手图标的下拉菜单，提供「并排」「浮动」「收起助手」，面板内不再重复放模式选择；原「任务」入口改名「工作进度」，默认展示需要关注和进行中的工作，已结束的工作与普通聊天记录分别收起，异常聊天保持可见。交付件用于查看当前 Bot 对话或任务产出的稿件、报告、图片、文件等成果，并可追溯来源任务；选择成果后在工作区预览或打开原文件。浮动模式的胶囊和输入区菜单继续提供展开、工作进度、交付件及完整记录入口。聊天、编辑器及按需打开的任务详情各使用稳定工作区面板。
5. Bot 名片默认关闭，点击信息按钮后在联系人旁覆盖展开，显示名字、职责和提示词摘要；「编辑资料」打开可滚动的编辑弹窗，提供保存和取消。名片采用清晰遮挡底面，点击外部或按 Esc 关闭并恢复触发按钮焦点；查看信息不挤动面板、不切换 Bot 或调用模型。导航收起时保留可通过键盘到达的名片入口。
6. 标题卡、功能卡、连续工作区和导航按外观方案使用对应材质；输入和覆盖层保留必要遮挡，正文共享所属外壳，不额外叠整层白色蒙版。普通消息、协作行、局部标题和任务字段以间距、分隔线及浅色状态区分，不重复叠加玻璃卡片。
7. 浮动答复覆盖正文时提高遮挡，避免底下文章透字；答复可单独收起，输入框可收回胶囊。只保留一个可编辑输入区，答复层不越过所属工作区或遮住固定设置与任务详情。
8. 导航样式、玻璃强度、主题与助手并排／浮动模式分别控制。经典／悬浮导航均可使用两种助手模式，切换外观不改变 Bot、业务对象、草稿、任务和执行上下文。
9. 2026-11-16 头像设计已落地：头像和颜色分开选，编辑弹窗用「角色 / 图形」切换；角色为默认，图形底色固定浅底，每个 Bot 各自选择，导航允许混排。规则见 [Bot 头像系统](design/bot-avatar-system-2026-11-16.md)；后续静态缓存与重复构建修复见完整方案第 12.6 节，保持既有悬停外框。

| 原生模块存储 | 保持稿件、书目、命例、项目和待办原权威来源 |
| 系统凭据配置 | 沿用现有加密方式，密钥由宿主读取，不进入记忆或名片 |

Bot 执行已改为 Pi JSONL 持久关联；主对话与对象/协作任务分别管理会话。通用工作台贡献本身不含业务工具，实际能力由模块装配；稿件沿用修改建议、确认和版本核对流程。

改造前基线为 `onosan-workbench 2.3.0`，原 `todo / bazi / reading / checkin` 都在 `life`。现已把 todo 的导航、scope 和快捷入口统一改为独立工作台 `todo`，保持原 `module=todo` 和业务数据 ID；原 life 聊天按真实 scope 分别归小历或工具助理，不整体搬迁。

主面板和灵动岛分别保存有版本草稿，已取消跨窗口编辑租约及手动交接。旧 `ai:chat:draft` 等无版本写入口拒绝改写 Bot 主对话和历史；限制在 Host/IPC 生效。

### 4.1 本地常驻与通信接入

采用通用方案第 7、8 节的持久消息、任务交接和事件唤醒；开源工程选型及官方源码入口统一维护在通用方案第 14.2 节。Pi 保持执行职责，OnO Host 负责寻址、收发记录、计划、通知和恢复。

执行层始终运行在独立、无界面的本地 Electron Host。收起助手、最小化或按原设置关闭主窗口留在托盘时，具备资源的任务继续。未开启独立后台时，明确退出 OnO 会保存中断状态并停止 Host，下次启动按原任务核对。

“设置 → 通用 → 独立 Bot 后台”开启 Windows 当前用户任务托管，通过认证命名管道连接。开启后 UI 完全退出仍处理有后台资源的任务；关闭开关撤销系统托管，随后退出 UI 停止后台。登录和每分钟恢复触发器监督实际 Host，单实例锁保证同一数据目录只有一个有效执行者。具体实测与物理登录/唤醒的验证边界见实施记录。

两种后台开关状态共用 OnO 数据根目录、身份和任务契约，界面显示 Host 连接及系统托管状态。等待确认保留待处理入口，恢复窗口不自动批准。电脑休眠或关机时停止推进，唤醒后核对收件箱、待回送结果和到期计划，避免重复执行或把所有错过的周期逐次补跑。依赖 OnO 窗口、浏览器及登录会话的能力单独核对可用资源。

### 4.2 灵动岛 AI 对话入口

按通用方案第 10.6 节，灵动岛 AI 对话已固定绑定 OnO 总 Bot（默认名 Ono）的 `botId + mainChatId`。`IslandAssistant.tsx` 使用相同 BotPanel/草稿协议，界面标题和空态使用总 Bot 资料；不再以旧 `module=todo` 和 `wb.island.ai.chat.v1` 决定提交目标。

灵动岛与总台使用同一 Host、对话控制器规则和持久状态，不另建会话或调用一次模型转发。用户可以在小窗发起跨领域请求，由总 Bot 委派；“打开完整对话”恢复总台的同一记录。两窗口通过 getDraft / saveDraft 分别读取与保存当前入口草稿，保存和提交校验本入口 revision；两处均可直接输入，提交仅清空来源草稿，重试沿用原请求 ID。同一 Bot 的请求由同一 Host 排队执行；关闭小窗不停止任务，也不改变主窗口正在使用的其他 Bot。旧共享草稿仅迁入主窗口，灵动岛初始为空。

旧灵动岛待办聊天和未发送草稿仍归待办 Bot，迁移后不再用旧选择键决定新入口目标。现有日程待办、提醒及外部 Agent 消息保持原归属；具体任务通知打开原 Bot/任务，不一律跳总台。灵动岛请求需要浏览器时由 Host 查找获准的业务窗口资源，不能使用小窗自身充当浏览器执行窗口。

## 5 OnO 迁移要求

### 5.1 原 scope 与历史归属

本节表格保留 11-16 首次七 Bot 迁移的输入规则，不可重新对已升级数据库执行。11-17 命理／阅读拆分以当前版本迁移为准：保留原混合主对话、草稿和任务，建立阅读独立身份并迁移书目专属历史，签到入口归总台。具体状态见[目录说明](README.md)与当前 `shared/bot-contracts.ts`；新增 P6 的用户主动开始新对话不是再次运行旧 scope 迁移。

按原聊天字段判断，以下 `viewId` 条件均限定 `module=workbench`；当前 pageScope 和页面选择不改写原来源。原 `chatScope()` 对缺失/无效字段的宽泛兜底不能直接当迁移规则：仅真正没有 module 的旧格式按原待办兼容，损坏记录先保留并标记。

| 原聊天条件 | 目标 Bot | 主对话候选资格 |
| --- | --- | --- |
| `module=todo`，或原格式无 module | `schedule` | 可参与日程主对话选择 |
| `viewId=todo` | `schedule` | 可参与；保留原 workbench scope 作为来源记录 |
| `viewId=home` | `coordinator` | 可参与；不吸收任何待办历史 |
| `viewId=workspace:media / copy / copy-publish / media-browser` | `media` | 仅无对象专属上下文的通用聊天可参与 |
| `module=copy` 且 draftId 有效 | `media` | 只挂历史，保留 draftId；不能改成不区分稿件的主对话 |
| `viewId=game` | `game` | 通用聊天可参与 |
| `viewId=browser / hush-hour / personal-website` | `web` | 通用聊天可参与，历史标签与站点授权不自动沿用 |
| `viewId=ai-test / ai-test-tasks / ai-test-history` | `ai-test` | 通用聊天可参与 |
| `viewId=workspace:life / bazi / reading / checkin` | `utilities` | 无对象专属或旧待办上下文的通用聊天可参与 |
| `module=bazi / reading` 且 profileId 有效 | `utilities` | 只挂历史，分别保留 module、profileId 与原消息 |
| `viewId=workspace:settings` 或 `settings-*` | 无 Bot 的旧历史区 | 只读，不生成主对话、不允许新任务 |
| 未知 module/viewId、应有但缺失的 draftId/profileId、损坏记录 | 带来源的旧历史区 | 不猜测归属；原数据保留，列入迁移异常清单 |

“有效 ID”首先指原记录字段完整可解析；业务对象后来删除时仍保留历史绑定，显示对象不存在，不重新归属。通用聊天只要 `contextScope / pageScope` 已绑定具体稿件、命例、阅读档案或另一个领域，就排除主对话候选；不清掉这些字段后强行合并。

每个 Bot 在合格候选中优先复用原记住且归属正确的聊天，否则按 `updatedAt` 降序、`chatId` 升序选取；无候选则建空主对话。以 `bots.main_chat_id` 与 `bot_chat_links` 的唯一 main 约束事务绑定，其余记录挂 history，不拼接消息。此后打开 Bot 使用稳定 mainChatId，不能每次运行 `preferredAiChat` 重新选择。

历史入口保留每条聊天、草稿、对象标签和原消息 ID。历史默认只读；继续处理时回到所属 Bot 主对话并由用户显式引用记录/对象。若主对话已有未发送草稿，不能用旧草稿覆盖；先让用户选择保留当前输入或复制旧内容。旧确认的过期状态不因迁移恢复为批准。

### 5.2 草稿、存储与入口迁移

1. 在新 Host 和两个 renderer 开始写入前，停止旧 AI 写入并做一致性备份；关闭所有连接后复制，或采用已验证的 SQLite 备份方式，不只复制正在使用的 WAL 主库文件。
2. 读取真实 schema 版本，移除 `AiStore` 固定写回 `user_version=1` 的行为；按阶段递增迁移，未知未来版本拒绝覆盖。新增 Bot 记录与现有 chats/settings 同库，不改写共享待办库或其他原生业务库。
3. 按第 2 节 seedKey 生成稳定身份，按第 5.1 节写入归属和唯一主对话；保留 chatId、消息 ID、正文、标题、draftId/profileId。默认 Bot 档案按种子补缺，不覆盖用户后来编辑的资料。
4. 草稿正文继续用 `chats.payload.draft`；关联行初始化 `draft_revision=0`，`draft_context` 保存可验证的回复目标及附件。`bot.ui` 仅保存模式、开关、宽度、上次 Bot 和每 Bot 工作区位置。旧租约不迁移，两个窗口首次打开重新申请。
5. 灵动岛新入口固定解析 `seedKey=coordinator`，旧 `wb.island.ai.chat.v1` 仅保留迁移来源，原 todo 聊天和草稿继续归小历。主窗口旧 life 下记住的聊天按真实 scope 恢复到小历或工具助理，不能只按旧导航 ID 搬迁。
6. 更新 `WorkbenchId`、NAV、view-to-workspace、默认 scope、页面上下文与快捷跳转的同一绑定；todo 的 viewId、事项 ID、共享库、提醒和同步协议不变。首页概况可继续跳日程页，不把旧首页功能随 Bot 导航一起删除。
7. 新 Pi 主会话只导入选中主对话的合格上下文并记录一次性标记；其他历史按显式引用读取。已有对象建议沿用原修改、确认、撤销与版本核对；未知外部写入先核对，不能由新 Pi 会话盲目重提。
8. 同时切换主面板与灵动岛到通用第 10.7 节协议；旧 `ai:chat:draft` 不允许无版本写入 Bot 聊天，旧 `ai:ask` 不与新 Host 并行启动同一任务。新任务恢复与旧 `recoverChats()` 分开，合法等待不能全部被旧逻辑置为过期。
9. 迁移结束输出各 Bot 主对话、历史数量及异常数量，核对旧记录总数和原 ID；成功提交 schema 与绑定后才启用导航。失败保持旧数据及备份可恢复，重复启动不再次生成 Bot 或导入历史。

### 5.3 回退与边界

回退前停止 Host 并保留新任务、交付件、草稿和 Pi 文件，再使用一致性备份恢复兼容版本；不能让旧程序打开未知新 schema 后写回版本 1。已发布文章、已创建待办或外部提交不随应用回退撤销，按真实业务回执处理。

迁移和业务写入已在隔离数据中验证；本次开发没有启动真实用户库升级。独立 Host 与系统托管已包含在本轮实现，原生浏览器、共享库同步及凭据边界保持有效。

## 6 CMO 复用与实施入口

CMO 的默认 Bot、能力、接口、存储、迁移及验收见 [CMO Bot 工作台改造实施方案](../../../design/cmo-bot-workbench-implementation-2026-11-15.md)，于 2026-11-18 校正已迁移核心并增加 M9 历史管理和剩余界面优化。当前协议 v7、数据库 6，分入口草稿取代旧租约；实现证据由 CMO 自身记录提供。下表保留业务映射摘要。

| CMO 当前工作区 | 领域 Bot 建议 | 可保留的原生模块 |
| --- | --- | --- |
| 首页 | 总 Bot | 总台入口与跨领域概况；待办及日程按独立领域组织 |
| 日程和待办 | 日程 Bot | 当前已独立的日程待办页，继续使用原共享业务库 |
| 权限管理 | 权限业务 Bot | 权限查询、群组创建 |
| 交付件管理 | 交付件 Bot | 当前项目交付件占位页，真实业务能力尚未接入 |
| PBI 管理 | PBI Bot | 特性管理、子系统与模块 |
| DTS 管理 | DTS Bot | 当前 DTS 占位页，真实查询能力尚未接入 |
| 设置 | 无 Bot | 人工设置、供应商、账号及接入配置 |

已核对的接入基础包括 `src/nav.ts`、`shared/ai-scope.ts`、`electron/ai-core.ts`、`electron/ai-ipc.ts`、`electron/ai-store.ts` 和实际模块贡献。CMO 同样使用 Pi、Electron IPC 和自有聊天库，可采用通用协议及界面控制器，业务规则由 CMO 保持。

CMO 接入需要特别保留：

- 权限 Bot 的名字表示权限管理业务职责，实际工具权限仍由 Host 和业务系统控制。
- PIC 群组、浏览器站点、W3 登录、WeLink 等能力逐项登记；群组提交已有内部确认，避免再叠加一次通用确认。“申请已提交”与“审批已生效”分别表达，结果不明时先核对。
- 普通工作台提示本身没有业务数据和专用工具；PBI、DTS、交付件等能力逐项接入，不因新增 Bot 档案就宣称已读写业务。
- CMO 当前 CodeAI 的 reply／failed 通知作为外部 Agent 事件接入，不直接等同于内部 Bot 协作或业务任务成功。
- CMO 灵动岛 AI 对话固定进入 CMO 自己的总助理，与总台共用主对话；不连接 OnO 总 Bot，任务通知仍按原负责人定位。
- CMO 独立管理自身名录、模型、凭据和 AI 数据。共享上游业务库仍服从原同步及归属规则，不自动与 OnO 合并聊天或记忆。

复用时替换领域名单、上下文提供器、工具、存储接入、路由及主题。共用的身份、会话、消息、任务、记忆规则和双模式状态保持一致。

## 7 实施与验收

按通用方案先验证 OnO 的身份和持久执行，再接入协作与恢复、托盘常驻、Bot 导航及双模式；随后实施独立 Host 阶段，总台完整首页单独重构。CMO 接入验证完成后再提取稳定共用包，维护同一份核心契约。CMO 按相同生命周期接入自身 Host，保持产品数据和凭据隔离。

| 阶段 | OnO 的实施结果 | 必须先验证 |
| --- | --- | --- |
| M0 契约与迁移 | 首期七 Bot，后续命理／阅读拆分为八 Bot；精确历史映射、唯一主对话、分入口草稿版本与提交 Host 契约 | 隔离副本重复迁移、失败回滚、未知 schema、对象历史隔离及同入口版本竞争 |
| M1 持久执行 | Pi 持久关联、任务接纳、提交去重、真实工具确认和恢复 | 回执丢失不重发，保存失败不清草稿，未知业务结果先核对 |
| M2 协作与交付件 | 直接消息、父子任务、结果回送与成果引用 | 小墨与小历完成一次实际交接；重复投递不重复业务写入 |

| M4 托盘与计划 | 持久计划、到期去重、唤醒补查及受控退出 | 隐藏后有资源的任务继续；空闲不调用模型；退出前保存中断状态 |
| M5 独立 Host | UI 与 Host 分进程、系统托管、资源桥 | 独立进程恢复与单实例；缺少窗口资源时准确等待 |

此前已完成 M0–M5，验证方式与限制见[实施与验证记录](bot-implementation-validation-2026-11-16.md)。M3 依据六张评审稿及通用第 10.8 节实现，运行证据不由图片替代。之后的原地协作、收发事件、回复时序与时间、局部面板切换、语音居中和性能修复归入完整方案第 5.5、12.6 节；新增长对话管理按 P6 待实施。CMO 独立记录实际迁移，本轮不改两项目运行代码。

除通用验收外，OnO 还需覆盖：

1. 总 Bot、待办及原快捷入口正确定位，旧聊天和共享业务数据可恢复。
2. 小墨整理稿件后与小历协作，结果回到原请求；“已接收”与“已完成”准确区分。
3. 外观组合、窄窗、浮动答复、并排展开、模式记忆及恢复一致，原生编辑操作可用；导航、材质、主题与助手模式可独立切换，面板内部不重复叠加玻璃卡片，覆盖答复不透出底层文字。主区域不再单列 Bot 身份行；名片可通过鼠标与键盘打开、关闭，不触发工作台切换或挤动布局。
4. 生成、等待协作、等待确认和失败时切换模式，草稿、对象、回复目标和后台状态不丢失。
5. 设置、实际写入确认、站点授权、灵动岛和通知原约束有效。
6. 托盘阶段关闭主窗口后，具备执行资源的跨 Bot 协作与定时任务继续；恢复窗口可定位结果，明确退出后停止后台工作。
7. 重启及休眠唤醒核对原消息、触发和业务回执，结果回原任务且不重复提交；空闲扫描不无条件调用模型。
8. 独立 Host 阶段验证 UI 完全退出、系统自启、实际进程异常拉起及单实例执行；首轮托盘验收不替代此项。
9. 使用真实模型和实际业务工具完成对应实施阶段的端到端验收后，再声明该阶段改造完成。
10. 主窗口处于任意领域时，从灵动岛发起消息仍进入 OnO 总 Bot；总台可继续同一聊天与任务，两处独立草稿互不覆盖，关闭/重开小窗不重复执行；旧待办聊天及原任务通知定位有效。
11. 使用含同名不同稿件/档案的隔离历史库验证：copy、bazi、reading 对象聊天只挂对应历史，不自动成为通用主对话；旧 life 下的 todo 被正确分离，损坏 scope 不被兜底导入小历。
12. 总台与灵动岛同时输入、草稿保存回执丢失、迟到防抖、中文组合、窗口销毁及 Host 重启均按通用第 10.7 节处理；已确认草稿可恢复，未确认缓冲不被宣称已持久化。
13. 七个 Bot 在窄窗及导航折叠下均可达，设置固定；业务标题卡保留。名片保存冲突、交付件空态/失效/无权限及浮动完整对话返回均有可验证行为。
