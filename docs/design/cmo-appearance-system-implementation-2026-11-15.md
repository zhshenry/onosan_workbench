**1. 目标、范围和实施依据**

目标是让 CMO 主窗口具备「导航样式 × 玻璃强度 × 主题」的独立切换能力，并统一内容表面的使用方式。用户可以选择现在的导航，也可以选择紧凑顶栏、居中侧栏的悬浮导航；玻璃强弱和主题不决定页面功能。

纳入主窗口、首页、日程待办、权限/PBI 的应用自有外壳、交付件/DTS 占位页、AI 面板、设置及菜单弹层。保留业务入口、数据来源、已保存布局和操作流程。桌面灵动岛保持现有独立视觉，内嵌网站保持网站自身的内容与样式。

依据的优先级为：用户最新明确要求 → 已确认的表面规则 → CMO 实际运行入口与业务约束 → 高保真中的视觉细节。原型说明、同名旧组件和图片中的示例数据不覆盖当前产品行为。

本次具体交付为五项：外观设置与迁移、八主题及背景、共用玻璃材质、两种导航呈现、页面适配与验收记录。以下内容不在本次范围：增加首页功能卡、开发交付件/DTS 业务、改造内嵌网站、重做 WeLink 同步、自动时段切换、自定义背景上传或额外的外观调节滑杆。

**4. 导航与窗口布局**

经典导航保留当前一体顶栏、侧栏、选中反馈及展开/收起方式。当前收起宽度约 66px、展开宽度 200px，继续沿用现有几何和顶栏测量。主题和材质仍可独立作用于这些容器。

悬浮导航按以下规则实现：

1. 顶栏分为四组：Logo 与导航开关、日程与待办、现有工具与头像、系统窗口按钮。左上角只保留 Logo 和开关，胶囊随内容收紧，不添加 CMO Workbench 或用户名文字。
2. 延续约 54px 的顶栏布局带，悬浮容器以约 50px 高度起步；沿用当前共享的顶部、边距和内容起点计算，内容区约在 74px 基准处开始。不得逐页另写固定偏移。
3. 收起侧栏约 60px 宽，展开约 200px；收起时选中入口为亮色圆片，展开时为可容纳图标与名称的胶囊。内容区随实际侧栏宽度让位，不横向压住业务页面。
4. 导航胶囊在「顶栏下方至底部设置按钮上方」的可用区域垂直居中，展开和收起遵循同一规则。以该区域的布局居中实现，不能相对整个屏幕简单设置 `top: 50%`。
5. 设置按钮独立固定在左下角。可用高度不足时导航胶囊最大高度受限、内部滚动，设置按钮和顶部 Logo 都保持可到达。展开/收起不改变同一组导航图标的纵向位置。
6. 保留窗口空白处拖动和双击最大化；按钮、输入、菜单及系统窗口按钮是可点击区域。不得让覆盖整条顶栏的拖拽层吞掉操作。
7. 继续使用 `src/topbar-layout.ts` 的真实宽度测量。长日程、后台任务、更新入口和窗口缩放时，按现有规则压缩/省略中部内容，不能硬编码原型的胶囊宽度或遮住右侧窗口按钮。

**5. 卡片、面板和无卡片区域的统一规范**

是否使用卡片由内容职责决定，适用于两种导航、两档玻璃和全部主题。透明底色不自动意味着卡片；控件、连续阅读底面、导航和弹层都可以有自己的表面。

| 内容职责 | 设计规则 | CMO 中的具体例子 |
| --- | --- | --- |
| 页面标题与说明 | 默认无独立底色、描边和投影，用字号、间距与对齐分层 | 我的看板、日期问候、日程待办标题与摘要 |
| 完整的独立功能模块 | 一张功能卡片包含本模块的标题、数据、状态、操作 | 首页「日程和待办」「AI 额度」 |
| 连续阅读与操作 | 使用统一工作区面板，内部按行、分区和分隔线组织 | 日程区、待办区、权限/PBI 工作区 |
| 容器内部的普通内容 | 不重复玻璃边缘、磨砂和外投影 | 单条日程、待办列表行、单个 New API 账号、图例和小标题 |
| 控件与工具组 | 具有自己的交互底面、边界和焦点态 | 搜索、日期切换、新增、筛选、单选选项 |
| 导航及覆盖层 | 使用相应导航/覆盖表面，范围清楚、遮挡充分 | 顶栏胶囊、侧栏、设置弹窗、任务编辑器、下拉菜单 |

「已有标题」或「可以点击」都不足以让内容成为独立卡片。空态、加载、报错保留在所属模块内，不额外弹出一个装饰卡片。账号分隔行、选中待办的浅色背景和输入框可以存在，但不因此拥有一整套独立玻璃效果。

工作区面板明确具有毛玻璃质感：强档外壳可见背景透色、磨砂、细亮边和柔和投影，内部共享阅读区更实；普通行只用间距、细线和浅色状态底。不是把整块工作区恢复成白色大卡，也不是让每条记录分别模糊。

CMO 的既有待办「列表/卡片」切换保留。这是用户明确选择的对象浏览方式：列表采用连续平整行；卡片视图可以保留对象卡边界，但以较实的浅底和弱分隔处理，避免每张对象卡再实时磨砂、强投影。不得因本规范删除卡片模式、改变默认选择或清空 `wb.todo.plan-view`。

经典界面原有标题卡是保留现状的兼容例外，不能作为「经典永远有标题卡」的新规范。本次默认保留这些既有标题卡，悬浮呈现按已确认高保真使用无卡片标题；两种呈现共用内容与状态，不复制页面。以后统一迁移经典标题区时，作为单独的内容表面改动记录；不能在新增主题或强玻璃时顺带拆除。该例外只对应存量标题卡，不能扩展为新页面的卡片判断规则。

权限/PBI 的标题、页签与地址栏属于同一连续工作区的框架，可以共享工作区外壳；不要再为标题单独套一张卡片。吸顶工具栏必须有稳定遮挡底面，其作用是防止内容穿透，不是制造另一层悬浮业务卡。

**6. 普通与强玻璃的材质规格**

普通档保持当前「柔和磨砂导航 + 清晰内容」的基准。换用八种新背景后颜色会变化，但内容不因普通档而变成高透明面板。强档只强化材质，布局、信息密度、圆角及控件尺寸保持一致。

| 表面角色 | 普通档 | 强档首轮调试值与表现 |
| --- | --- | --- |
| 导航外壳 | 沿用当前导航材质基准 | 方向性浅色渐变，亮端约 0.66、透色端约 0.30，暖主题允许温和偏暖 |
| 功能卡/工作区外壳 | 当前近白、较实底面 | 浅色覆盖约 0.44–0.60；背景色层可见但背景细节被模糊 |
| 连续阅读区 | 清晰稳定的阅读底面 | 共享浅底约 0.78–0.94，不逐行增加滤镜 |
| 输入与轻量控件 | 延续现有清晰控件 | 使用较实浅底，焦点边界明确，避免背景细节穿过输入文字 |
| 菜单/对话框/吸顶区 | 足够遮挡底下内容 | 底面约 0.92–1.00，以边缘与层次体现材质，不透出另一层文字 |
| AI 面板 | 延续当前阅读体验 | 外壳接入面板材质，编辑区更实；覆盖内容时使用覆盖层遮挡强度 |

强档大表面以 `blur(30px)` 起步，允许在 28–32px 内对照调试；饱和度先取 1.4，在约 1.3–1.6 内调整。原型 A+ 的 1.85 不直接套用到照片背景。上沿/左上沿为细亮边，下沿为弱暗边，配一层接触阴影和一层柔和外投影。不增加持续流动的高光。

实际颜色取主题中性色，表中透明度指背景覆盖层，不给整个容器设置 `opacity`。多层合成后必须看实际画面；若阅读区不清晰，提高阅读底面遮挡，而不是继续加大 blur。玻璃装饰层不承接鼠标、不遮住键盘焦点。

沿用当前排版 token 和基础圆角：CMO 当前主面板约 18px、卡片约 14px。悬浮导航可以使用胶囊形状；不要照抄原型把全部内容统一放大到 24/34px 圆角，也不随强弱玻璃切换圆角。正文、标题、数字等继续遵循项目 typography 检查规则。

CSS 按实际消费者分工：主题提供背景、文字中性色、强调色；材质提供导航/面板/阅读/控件/覆盖层表面；导航提供位置与尺寸。`--workbench-card-bg` 等参与 `color-mix()` 的值继续是纯颜色，外层渐变另用背景变量。不要把所有 `.glass` 或全部白色背景一次性替换成同一种透明渐变。

**7. 主题、光线与素材**

为减少旧设置迁移，保留 `mist`、`warm` 两个已有标识并更新其显示名和背景定义，其余主题使用新增标识。标识只是存储值，不表示保留旧背景图。

| 显示名 | `uiTheme` 值 | 视觉来源 | 底色 / 强调色起点 | 主题方向 |
| --- | --- | --- | --- | --- |
| 雾珀 | `mist` | 第一套 A，`data-scheme="a"` | `#e8e9ec` / `#4a67a3` | 灰雾底，蓝、杏、青、淡紫色场 |
| 暖砂 | `warm` | 第一套 C，`data-scheme="c"` | `#eee4d7` / `#8f5b25` | 暖砂、奶油与浅绿，避免通屏泛黄 |
| 青瓷 | `celadon` | 第一套 E，`data-scheme="e"` | `#e6ede8` / `#2e7d6b` | 灰绿、浅青、奶油 |
| 藤紫 | `wisteria` | 第一套 F，`data-scheme="f"` | `#eae8f1` / `#6a5aa8` | 薄紫、柔粉与少量蓝 |
| 蔷薇 | `rose` | 第一套 G，`data-scheme="g"` | `#f0e9e5` / `#96586a` | 灰粉、淡桃、藕紫 |
| 燕麦 | `oat` | 第一套 H，`data-scheme="h"` | `#eceae4` / `#68755a` | 米灰、浅卡其，保持中性 |
| 窗影 | `windowlight` | 第二套 A；E 共用同一背景 | 采用原图与遮罩 / `#3c5c97` | 灰泥墙、窗格光、树影，三时段 |
| 空间窗景 | `spatial` | 第二套 B | 采用原图与遮罩 / `#2f66c9` | 柔焦房间纵深，克制照片饱和度 |

六种色场提取第一套基础方案的 `--field-base`、`--blob1` 至 `--blob4`、文字中性色与强调色，以及共用背景构图；使用静态渐变/色场层。不要一起导入基础方案各自的 blur、圆角、间距、业务色，也不要使用加号方案更浓的背景。切换强玻璃时六种主题的背景必须完全相同。

窗影共用 `glass-a-komorebi-wall.jpg`，三时段以同一图片的构图、滤镜和遮罩表达，不需要再生成三张图：

| 时段 | 背景处理起点 | 验收重点 |
| --- | --- | --- |
| 上午 | 参考原型背景水平翻转，`saturate(.78) brightness(1.08) hue-rotate(-6deg)` | 更清亮，标题不能落在最亮光斑上失去对比 |
| 午后 | 原图基础构图，暖光与冷灰阴影平衡，初始裁切参考 `38% 42% / cover` | 与已确认高保真对照，保持墙面与窗影层次 |
| 傍晚 | 参考 `saturate(1.6) brightness(.84) sepia(.32) contrast(1.12) hue-rotate(-8deg)`，再按可读性收敛 | 暖夕照可辨，深影上次级文字仍清晰 |

这些变换只作用于背景层，不能翻转整个界面或给正文加色彩滤镜。背景默认静止；手动换光线可做短淡入，减少动态效果模式下直接切换。不增加按系统时钟自动切换。

空间窗景使用 `glass-b-room.jpg`，初始采用 `center 46% / cover`、温和柔焦与明暗遮罩。可参考原型的 `blur(1.6px) saturate(1.05)`，但该滤镜属于背景处理，不随玻璃强度变化。窗口变化时不能露白边，主要光影应仍能从容器间隙看见。

裸露标题的可读性优先通过背景构图、明暗和无明显边界的局部遮罩解决。不要为了亮背景再悄悄恢复一个带描边和投影的标题卡。
