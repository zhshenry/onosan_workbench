# ONO 外观系统实施与验收记录

实施基线：已发布的 v2.2.0（`ae67acc`）；最初在独立分支 `codex/ono-appearance-system` 实施。2026-11-15 已将本次 UI 改动同步至日常项目目录 `C:\Myself\vibe_coding\onosan_workbench`，可在该目录启动开发版。没有发布新的安装包。

## 已实现

- 「设置 → 通用与外观」提供经典/悬浮导航、普通/强玻璃、八套主题及窗影上午/午后/傍晚。八主题为雾珀、暖砂、青瓷、藤紫、蔷薇、燕麦、窗影和空间窗景。四项设置独立组合、实时预览、落盘并在重启后恢复。
- 经典保留原导航几何；悬浮顶栏拆为四组，左上只有 Logo 和展开按钮。主导航在顶栏与独立设置按钮之间居中，窄高不足时内部滚动。二级目录保留原鼠标和键盘操作。
- 按实际界面反馈，页面标题、说明与主操作在两种导航下均使用标题卡片；完整功能使用功能卡；待办、阅读、签到、博客、游戏、AI 测试等连续工作区使用统一磨砂面板。已在面板内的标题与普通行不重复套毛玻璃。功能工具栏、显式组件卡片样式和控件自身底面保留。
- 普通与强玻璃使用同一组表面绑定：普通为轻磨砂、少量透色，强档增加透色、模糊与边缘层次；不更换布局尺寸、字阶或业务组件实例。窄窗口中覆盖内容的 AI 面板在两档下均使用更不透明底色。未改灵动岛、终端、网页原生内容和星盘本体。
- `cool/sunny` 迁移至 `mist`，缺失的新设置落到经典/普通/午后。保存使用四项外观快照串行写入，迟到响应不回写新选择，失败恢复最后成功值并可重试。其他应用设置使用原接口及存储。
- 已有看板自由布局、卡片样式、真实签到/额度、业务草稿和任务数据均沿用 v2.2.0 的实现。

## 实机反馈修订与复核（2026-11-15）

用户指出普通模式下首页纯白、游戏页有玻璃，以及标题直接放在背景上的差异。本轮统一了运行时规则，并同步通用方案和 CMO 实施方案；首版高保真中的裸标题不再作为实施规范。

- 普通面板统一使用白色约 .76→.64、18px 模糊、1.15 饱和度及轻投影；强面板统一使用约 .66→.50、30px 模糊、1.4 饱和度及亮边/接触阴影。同级标题、功能卡、连续工作区共用同一组 token，不再在部分工作区叠加整层白色阅读蒙层。
- 去掉悬浮模式的透明标题覆盖，首页、待办、阅读、签到、游戏与测试任务等独立页头均有卡片。补齐待办标题的内边距、边框和圆角；已经处于工作区内的标题共享原外壳。
- 控件与覆盖层保留清晰底面；修正共享选择器的优先级，使窄窗 AI 覆盖层能够正确提高遮挡。游戏扩大预览的既有平整外壳不重复叠玻璃。

本轮 `npm run verify` 与 10 项外观/设置定向测试通过，日志保存在 `test-results/appearance-materials/`。Electron pilot 通过 10 组验收、40 种外观组合并生成 29 张截图，渲染错误为 0；新增两档材质跨首页、游戏、待办、阅读、签到及测试任务的实际背景、模糊、边缘和投影一致性检查。继续通过尺寸/挂载保留、博客草稿、键盘、1024×680、减少动态与重启恢复检查。截图与最新报告位于 `test-results/appearance/`；初版报告可从整理备份中追溯。
