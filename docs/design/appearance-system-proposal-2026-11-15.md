**本次依据与范围**

已核对两套原型的方案定义、切换逻辑和设计说明，并结合保存的参考图、当前应用截图及当前源码分析。两套原型都不只是链接初始打开的那个页面：第一套有六种基础配色及各自的强玻璃版本；第二套的 B/E 共享悬浮导航，A/E 支持光线切换。

当前应用的已保存截图用于判断材质，最新结构和交互以当前源码为准。本次没有完成运行版的逐页视觉、对比度或性能验收，下文的参数和检查项属于实施目标。

本方案采用以下范围假设：

- 主窗口及其自有的设置、菜单、弹层、AI 侧栏统一接入外观选项。
- 「保持当前样式」指保留当前顶栏、侧栏的结构与交互；选择其他主题后，其配色仍跟随主题。
- 普通玻璃统一为轻磨砂、少量背景透色；强玻璃增强透色、高光边和层次。切换玻璃不改变背景、排版、圆角或控件尺寸。
- 根据 2026-11-15 最新反馈，窗影改为跟随电脑本地时间自动切换：06:00–12:00 上午、12:00–18:00 午后，其余时间使用傍晚光线，各区间含起点、不含终点。替换原手动选择，不增加自动/手动模式开关。
- 工作台现有业务布局继续使用，包括首页卡片位置、待办分区、编辑器和浏览器。独立 Island 窗口、终端、命理盘面、嵌入网页等已有专用视觉保留其领域语义；相关主题读取代码需要兼容新设置值。

**一、最终提供哪些选项**

| 设置项 | 选项 | 负责改变什么 |
| --- | --- | --- |
| 导航样式 | 经典、悬浮 | 顶栏分组、左侧导航容器、设置按钮的位置与外形 |
| 玻璃强度 | 普通、强 | 表面透明度、磨砂、高光边、投影 |
| 主题 | 雾珀、暖砂、青瓷、藤紫、蔷薇、燕麦、窗影、空间窗景 | 背景、主题强调色、中性色温 |
| 窗影光线（自动） | 按系统时间计算上午、午后、傍晚 | 窗影背景的光斑方向、位置与色温；不作为持久化偏好 |

导航展开/收起和 AI 开关仍由现有按钮控制，不与导航样式绑定。更换样式时保留这两个状态。

八种主题与两种导航、两档玻璃形成 32 种基本组合；计算窗影的三个时段后，共 40 种外观组合，尚未计入导航展开/收起和 AI 开关。

A+、C+ 等不再占用主题位置：「雾珀 + 强玻璃」对应 A+ 的材质方向，「暖砂 + 强玻璃」对应 C+ 的材质方向。第二套 E「融合」也不需要成为第九个主题，选择「悬浮 + 窗影」即可组合出其导航与背景方向。

**二、当前与参考设计的主要差距**

| 当前情况 | 与参考图的差距 | 优化决定 |
| --- | --- | --- |
| 主题同时定义背景、配色和 blur | 更换颜色会连带改变材质，无法独立组合 | 将背景配色与材质参数分开 |
| 首页、待办等外层卡片使用不透明白色 | 大部分背景被遮住，同档材质跨页面不同 | 两档均接入同一组面板；普通轻磨砂，强档增强透色与边缘，输入和覆盖层保持清晰底面 |
| 多类表面共用同一个白色背景变量 | 直接全局改透明会同时影响菜单、输入框、吸顶表头 | 按用途区分面板、阅读区、弹层，并区分纯颜色与渐变背景变量 |
| 部分 AI 侧栏按工作台覆盖为纯白、无模糊、无投影 | 同一 AI 面板切换工作台后材质不同 | 两档均统一 AI 外壳；输入控件保留清晰底面，覆盖模式提高遮挡 |
| 主要靠浅底、描边、统一阴影表现玻璃 | 缺少高光方向、厚度和前后层次，容易看成半透明白卡 | 强玻璃增加亮上沿、弱暗下沿、接触阴影与扩散投影 |
| 当前背景多为已处理的柔雾贴图 | 背景细节少时，继续提高 blur 的视觉收益很低 | 用六种有层次的色场、窗影和房间背景提供可被模糊的内容 |
| 导航为整条顶栏和纵向容器 | 不具备 B/E 的独立悬浮形态 | 新增共享交互下的悬浮样式 |
| 原型采用固定画布，并有整体缩放 | 不能证明真实小窗口、长标题、多任务状态适配正确 | 复用正式应用的测量和响应式逻辑，按实际窗口验收 |

这里有两个容易误判的点：

第一，当前 cool/warm 使用较小 blur，同时背景图片本身已经柔化，不能仅凭 blur 为 2px 就认定实现有问题。玻璃感取决于背景、透明底色、边缘和投影共同作用。

第二，当前白色内容卡片有明确的可读性目的。它们是新增强玻璃时需要区分处理的表面，不应全部视为错误并删除。

**三、导航样式的具体设计**

经典样式沿用当前一体顶栏、侧栏容器、选中条和展开/收起行为。根据最新反馈，两种样式共用收起 66px、展开 200px 的侧栏占位，以及同一套顶栏控件位置和内边距；切换样式不改变其他内容的坐标或尺寸。主题和玻璃档位可以单独作用于其材质。

悬浮样式采用 B 的分组方式和 E 修正后的导航规则：

1. 顶栏分为四组玻璃容器：Logo 与导航开关、日程与待办、工作台工具与头像、系统窗口按钮。左上角只保留 Logo 和导航展开/收起按钮，不显示“Ono Workbench”等名称；胶囊按两个图标的内容宽度收紧，参考用户补充的图二。工具组继续容纳现有任务、更新、Island 和 AI 等入口，日程/待办保持作为一组整体定位。
2. 顶栏容器之间露出背景，空白区域仍可拖动窗口；按钮、输入和弹层保持可点击，窗口最小化、最大化、关闭行为保持正常。
3. 左侧导航使用 66px 的收起胶囊、200px 的展开胶囊，与经典占位一致。一级按钮约 44px，选中项为亮色圆片，展开后延伸为胶囊；形状和内部排列不影响工作区预留空间。
4. 悬浮导航胶囊在顶栏下方、底部设置按钮上方的可用区域垂直居中，展开和收起共用这一规则。子目录改变胶囊高度时重新居中；同一工作台展开/收起时保留分支高度，使一级图标的位置保持稳定。
5. 当前工作台的子目录在收起时保留高度，以圆点表示当前分支；展开后显示名称。切换展开/收起时一级图标的位置保持稳定。
6. 收起状态复用现有悬浮子菜单和键盘焦点逻辑；展开后直接展示子目录。装饰圆点不承担难以点击的小尺寸交互，实际操作仍通过正常大小的菜单项。
7. 设置从导航胶囊分离，固定在左下方。导航内容过长时内部滚动，设置仍可到达。

尺寸适配建议：保留正式应用约 54px 的顶栏布局带，将约 50px 的悬浮容器置于其中；工作区顶部仍围绕现有 74px 基准对齐。具体内边距以实际窗口对照为准，不复制原型的固定坐标。

现有顶栏会测量右侧工具宽度并避让中部信息，这套逻辑应继续使用，只调整分组后的测量范围。原型中固定宽度的胶囊无法覆盖长日程标题、多个后台任务、不同窗口缩放等情况。

同时打开展开导航和 AI 时，沿用各工作台已有的收缩、换列或覆盖策略，检查最窄可用宽度。样式切换不自动替用户收起导航，也不覆盖首页保存的卡片布局。

经典/悬浮切换增加约 240ms 的过渡：侧栏入口从顶部排列平滑归位到居中排列，玻璃底面交叉淡化，反向同理。只让导航内部和装饰底面参与，其他内容在动画中途也保持原位；图标和正文不缩放。连续反向切换从当前画面衔接，不排队播放；首次恢复设置或系统减少动态效果时直接呈现，中途启用减少动态效果立即结束动画。

用户指定的是 B/E 的顶栏与侧栏，因此不把原型「整个内容区再套一扇大玻璃窗」作为本次必要结构。直接让现有内容卡片使用正确材质，可以保留当前页面结构，也能避免外层玻璃叠加不透明内层后失去透色。

**卡片与表面的使用规范（2026-11-15 已确认）**

核心规则：是否使用卡片，由内容的职责和操作范围决定。导航样式负责导航布局，玻璃强度负责材质，主题负责背景与配色，都不作为增删内容卡片的理由。卡片的边界应表达「这是一组可独立理解、独立使用的内容」，不能只是为了给每个标题或按钮加一个框。

有底面不等于使用卡片。需要分别识别页面标题、内容卡片、连续工作区、内部阅读底面、控件、导航和弹层；它们可以共享配色与材质规则，但不应都画成同一类悬浮卡片。

| 内容职责 | 容器规则 | 工作台中的例子 |
| --- | --- | --- |
| 页面标识与说明 | 标题、说明和主操作统一置于标题卡；已在工作区内的标题共享外壳 | 「我的看板」、日期、问候语、页面说明 |
| 完整的独立业务模块 | 使用内容卡片，标题、数据、状态和本模块操作放在同一容器内 | 今日摘要、专注计时、每日签到、AI 额度 |
| 连续阅读、编辑或操作区域 | 使用一块稳定的工作区面板，内部以分区和分隔线组织，不把每行都拆成卡片 | 日程列表、待办列表、表格、编辑器、测试结果区 |
| 已在卡片或面板内的内容 | 默认不再套卡片；用间距、分隔线、选中态或较实的阅读底面区分 | 待办行、额度中的单个账号、图表图例、局部小标题、空态和加载态 |
| 单个控件或轻量工具组 | 按控件用途提供底面、边界和焦点态，不额外包一张大卡片 | 添加卡片按钮、搜索框、日期切换、筛选、分段控件 |
| 导航与窗口操作 | 使用导航表面，边界对应导航组的操作范围 | 顶栏胶囊、侧栏、独立设置按钮 |
| 覆盖其他内容的界面 | 必须有独立且足够遮挡的表面，阴影表达覆盖层级 | 悬浮子菜单、下拉菜单、对话框、覆盖模式的 AI 面板 |

判定顺序：先判断内容是否已经属于某个容器；已有归属时优先沿用父容器。独立页头作为页面标识区使用标题卡。拥有独立数据、状态和操作范围的完整功能单元使用功能卡。长列表或编辑流程使用连续面板。输入、吸顶及覆盖层提供各自底面，不因此再套业务卡片。

一块区域有自己的标题，并不足以成为卡片；需要独立滚动，也不必增加卡片边框。数据为空、加载中或报错时，原功能卡片保留，状态在卡片内呈现。普通列表项即使可点击、可完成或可删除，也不默认变成卡片。

对象卡片的例外：当每个项目都具有独立封面、摘要、状态和操作，且以平铺方式供浏览或比较时，可以各自成卡；此时整个网格通常不再套同等强调的大卡片。不能仅因为一条记录有按钮就将其卡片化。

层级限制：同一内容区域默认只使用一层承担主要分组作用的悬浮容器。卡片内允许输入框、浅色阅读区和选中态，但不重复一整套高光边、实时磨砂和投影。卡片本身也不要求同时拥有强边框与强阴影，材质应服从内容层级。

应用到首页：

- 「我的看板」、日期、问候语与右侧「添加卡片」「编辑布局」共用标题卡片；两种导航均如此，按钮保留自己的交互底面。
- 今日摘要、专注计时、每日签到、AI 额度各是一块功能卡片。其标题与内容在同一容器内，不再给标题套独立小卡。
- 今日摘要中的图表、每日签到中的平台项、AI 额度中的账号行，默认在已有卡片内平铺，使用分隔线或弱底色即可。
- AI 助手作为独立工作区有面板；输入框和上下文区可有更实的阅读底面，不再为每一行消息或说明增加悬浮卡片。

应用到日程待办：页面标题、解释文字与右侧「新增」共用标题卡片。左侧日程面板包含日/周切换、日期选择、周日期条、今天的日程及明日预告；右侧待办面板包含计数、「全部事项」入口和连续列表。三块表面共用同一档玻璃，内部行通过细线和状态区分，不独立成卡。

图中「整理本周工作计划」的浅蓝底是行状态强调，没有独立投影或磨砂；「今天的日程」小标题、两条日程和明日预告也没有各自的卡片边界。这些是后续实现其他连续工作区时应复用的具体示例。

应用到设置：设置窗口本身有弹窗表面，分类导航有导航表面。「通用与外观」等页面标题不单独成卡；相关设置可以按一个完整主题组成浅色分组，组内各行用间距或分隔线组织。主题缩略图属于选择控件，可有选中边界，不再给每个标签、说明和开关套卡片。

2026-11-15 实机反馈取代首版标题兼容安排：经典与悬浮导航均使用同样的标题卡片，不再保留“经典有卡、悬浮无卡”的分叉。标题卡与下方功能卡并列，不能把整个页面再罩入一个大面板。

标题卡在全部主题及窗影三个时段下都必须清晰可读，材质与同级功能卡一致。已在工作区或设置弹窗中的标题共享所属容器，不额外套卡；吸顶工具栏保持遮挡，防止滚动文字穿透。

**四、普通与强玻璃的材质规则**

普通档保持当前「柔和玻璃导航 + 清晰内容卡片」的观感。重点是让新主题正确覆盖背景与配色，统一共享表面的使用方式，不把普通档偷偷变成另一套高透明样式。

强玻璃采用 A+/C+ 的方向性高光、透色和投影。只提取材质，排除原型中与其同时改变的背景色场、装饰光斑、卡片间距和圆角。

工作区面板、标题卡与功能卡共用玻璃材质，只按内容职责区分组织方式。普通档与强档均有背景透色和磨砂；内部普通行不单独模糊、投影或描绘悬浮边界，不另叠整层白色蒙层。

| 表面用途 | 普通档 | 强玻璃档 |
| --- | --- | --- |
| 顶栏、侧栏 | 当前磨砂和边框 | 明显透色、方向性亮边、中等悬浮投影 |
| 标题卡、功能卡、工作区面板 | 白色约 .76→.64，18px 模糊，1.15 饱和度和轻投影 | 白色约 .66→.50，30px 模糊，1.4 饱和度和更明确的边缘/接触阴影 |
| 内部文字、列表与输入 | 普通行共享外壳；输入控件保留较实底面 | 普通行共享外壳；输入控件约 .85，不为每行重复增加滤镜 |
| 菜单、弹窗、吸顶表头 | 稳定的高遮挡底面 | 仍然高遮挡，强化边缘与投影，避免叠字 |
| AI 侧栏 | 外壳接入普通材质，输入区清晰；覆盖模式提高遮挡 | 外壳接入强材质，输入区清晰；覆盖模式提高遮挡 |

以下面板数值已同步至 ONO 的 `src/appearance.css`，其他产品实施时需验证实际背景和屏幕：

- 参考 A+ 的白色渐变约 0.66 → 0.30，C+ 的暖白约 0.68 → 0.32，先用于导航等装饰性较强的表面。
- 面板普通档白色覆盖约 .76–.64、强档约 .66–.50，所有同级面板共用；输入控件约 .85、弹层约 .92–1.00。不得只给强档接入，也不得在某页额外叠加整层白色蒙层。
- 强档大面板 blur 先在 28–32px 内调试。原型 A+ 饱和度达到 1.85，但照片背景下不宜无差别照搬；先以 1.3–1.6 为调试范围，避免窗影变黄、空间背景过艳。
- 上沿和左上角形成细亮边，下沿保留很弱的暗边，使用一层接触阴影和一层柔和外投影表现厚度。AI 和弹层的投影略强于普通卡片。
- 如增加砂面颗粒，应是极低强度、静态、不可干扰文字的材质细节，不新增用户调节项。

实现时透明度作用于背景层，不能给整个面板设置 opacity，否则文字和控件会一起变淡。也不把所有列表行都做成独立实时磨砂：外层面板负责玻璃，内层阅读区主要使用浅色底面，避免嵌套模糊增加开销、破坏层次。

设置弹窗需要独立考虑：遮罩已经压低背景对比，不能再照抄主界面低透明度参数。保留分类导航、内容底面、设置分组的可辨层次，强档只在外框与合适的空白区域体现材质。

**五、八种主题如何落地**

| 主题 | 来源 | 背景与气质 | 强调色方向 |
| --- | --- | --- | --- |
| 雾珀 | 第一套 A | 灰雾底，蓝、杏、青与淡紫形成柔和色场 | 雾蓝，参考 #4a67a3 |
| 暖砂 | 第一套 C | 暖砂、奶油、浅绿，整体温暖但避免泛黄 | 棕金，参考 #8f5b25 |
| 青瓷 | 第一套 E | 灰绿、浅青与奶油色，清爽克制 | 青绿，参考 #2e7d6b |
| 藤紫 | 第一套 F | 薄紫底，少量粉与蓝形成层次 | 藤紫，参考 #6a5aa8 |
| 蔷薇 | 第一套 G | 灰粉、淡桃、藕紫，降低装饰色饱和度 | 玫瑰灰，参考 #96586a |
| 燕麦 | 第一套 H | 米灰、燕麦、浅卡其，最中性的一组 | 灰橄榄，参考 #68755a |
| 窗影 | 第二套 A | 灰泥墙、窗格光和树影；带上午/午后/傍晚 | 雾蓝，参考 #3c5c97 |
| 空间窗景 | 第二套 B | 柔焦房间照片，保留室内纵深 | 系统蓝，参考 #2f66c9 |

六种色场使用基础方案 A/C/E/F/G/H 的背景，不因为选择强玻璃而换成加号方案的更浓背景。背景应具备低频渐变和少量中频轮廓，使透明区域可见色层，避免只有一整块均匀灰色。

窗影的三个时段：上午偏清亮，午后暖光与冷灰树影平衡，傍晚降低亮度并增加夕照色温。复用原型的本地素材及构图处理方式，不假定需要三张不同照片；背景裁切随窗口变化，重要光斑不应恰好长期藏在导航后。

空间窗景复用原型现有本地房间素材，以 cover 适配窗口，并固定一套温和的亮度、饱和度和遮罩处理。自定义照片、背景调节滑杆不在本次必要范围。

原型窗影有缓慢漂移和呼吸动效。此次建议默认使用稳定背景；光线切换可做短淡入，系统要求减少动态效果时直接切换。先确保材质和可读性，再决定是否需要持续动效，避免持续变化的光影干扰工作。

主题色用于选中态、焦点、常规强调。业务语义单独保持：完成用绿、逾期/错误用红、日程与待办图表保留稳定可区分的颜色、AI 标识继续使用既有语义色。不能在青瓷主题中让「待办」和「完成」都因继承强调色而变成同一种绿。

参考 E 的颜色收敛原则，额度进度等普通数量表达可统一为主题强调色，减少大面积品牌色底；品牌仍由原有图标和名称识别。命理五行、状态告警等有业务含义的颜色不参与这种收敛。

**六、设置中的呈现方式**

继续放在现有「通用与外观」分类内，不新建另一套设置入口。

建议排列为：

1. 导航样式：两个小型结构预览卡，「经典」「悬浮」，一眼能看出顶栏和左侧导航的区别。
2. 玻璃强度：两个选项，「普通」「强」。预览使用同一个背景，避免把背景差异误当成玻璃差异。
3. 主题：八张带名称的真实背景缩略图，宽内容区最多四列，较窄时两列；选中态使用边框和勾选标记，不只靠颜色。
4. 光线：只在选中窗影时显示「窗影时段 · 自动」、当前时段和时间规则，切回窗影使用当前系统时间。背景与缩略图同步更新。

沿用点选即保存并生效的体验，不要求重启。快速切换时以最后一次选择为准；保存失败提示并恢复最后成功保存的状态。键盘可依次聚焦、切换和确认选项，读屏能识别当前选中项。

导航、玻璃和主题都只更新外观，不重新挂载工作台页面。待办草稿、编辑器光标、AI 对话与流式输出、浏览器标签和历史、当前滚动位置均应保留。

升级默认建议保留「经典 + 普通」，避免用户升级后导航布局突然改变；主题迁入新的八选一。新安装默认使用「经典 + 普通 + 雾珀」。窗影初次选择与重启均读取电脑本地时间；每分钟边界及窗口重新激活时同步，不因时钟变化写配置。旧手动光线字段兼容读取，但不参与显示和外观保存快照。

旧主题迁移建议：mist → 雾珀，warm → 暖砂，cool 及更早 sunny → 雾珀。后两者在新主题中没有精确对应项，这是替换主题列表时的近似迁移，应在变更说明中讲清楚；其余设置和导航展开状态保留。

**八、实施顺序与每步验证**

1. 建立设置字段、旧值迁移与表面角色。验证旧设置读取正常，经典/普通基准与现状对得上，业务界面状态不因切换重置。
2. 接入八主题及窗影三个光线。验证所有背景本地可用，主题色不覆盖业务语义，重启后选择保留。
3. 在首页和日程待办完成强玻璃样板。使用同背景、同数据、同布局对照普通与强档，确认差异来自材质，再推广到 AI、设置和其他工作台。
4. 实现悬浮导航和顶栏。验证展开/收起、悬浮菜单、短窗口滚动、窗口拖拽及系统按钮；检查导航与 AI 同开时的内容空间。
5. 完成组合检查与原生应用验收。对照参考图调整细节，记录低对比背景、照片背景和小窗口的结果，再完成文档与变更说明。

每一步交付都应能单独对照，不先把所有页面透明化后再补可读性。

**九、验收标准**

外观与组合：检查 40 种外观状态，导航/玻璃/主题完成切换与持久化检查，窗影三个时段通过模拟本地时间覆盖；验证 06:00/12:00/18:00 边界、跨午夜、唤醒与重启后重新取时，并确认自动切换不写配置。每种主题至少在首页、待办页比较普通/强玻璃，其他工作台重点检查外层面板、输入区和菜单。窗影的三个时段均检查文字压在最亮/最暗背景上的效果。

独立性：切换玻璃不改变背景、卡片尺寸与间距；切换主题不改变导航样式或展开状态；切换导航不重置主题、玻璃、AI 开关和当前业务页面。同一展开/AI 状态下，切换导航前后对比主内容、标题、卡片、顶栏控件、AI 及设置弹窗的坐标与尺寸，须保持一致；主动展开/收起仍允许按原行为改变内容宽度。

表面层级：两种导航均使用标题卡，功能模块边界与数据及操作范围一致；列表行和局部标题不重复套卡片，控件与弹层按自身用途提供底面。普通/强玻璃作用于同一组表面；切换主题、导航或材质不增删内容容器。

布局：覆盖默认 1280×820、最小 1024×680 及一个更宽窗口；在 Windows 125%/150% 缩放下检查。覆盖两种导航的展开/收起、AI 开/关、AI 宽度范围及较长顶栏内容。设置、菜单和窗口按钮不得越界或被遮挡。

可读性：普通正文以至少 4.5:1 为目标，大字以至少 3:1 为目标；关键控件边界和焦点标识可辨。透明表面必须在实际合成背景下检查，不只测前景与声明底色。选中、完成、错误不能仅靠颜色区分。这里是验收目标，不代表当前已测得这些结果。

交互：悬浮导航在顶栏与独立设置按钮之间垂直居中，设置按钮始终固定在左下角；同一工作台导航展开/收起时图标不跳动。鼠标能稳定进入悬浮菜单，键盘可到达各入口；样式切换保留草稿、焦点、滚动位置、浏览器状态和 AI 流式输出。窗口拖拽、双击最大化及三枚系统按钮正常。

性能：用同一机器、相同窗口、相同列表和 AI 场景比较前后滚动与缩放表现，记录明显掉帧和持续重绘。优先减少嵌套滤镜、静态化背景；不通过悄悄切回普通档掩盖强档开销。无需为每条列表记录增加独立模糊层。

自动化验证集中在有行为风险的设置迁移、保存失败/快速切换和顶栏布局计算；视觉材质通过实际截图与人工对照验证，不为每个 CSS 数值编写镜像式测试。

**建议首先打样的三组**

- 经典 + 普通 + 雾珀：兼容基准，确认新增外观系统不会破坏当前使用习惯。
- 经典 + 强玻璃 + 雾珀：保持相同布局和背景，单独检验 A+ 材质是否成立。
- 悬浮 + 强玻璃 + 窗影·午后：检验 B/E 导航、窗影与完整玻璃层次的组合。

随后用「悬浮 + 强玻璃 + 空间窗景」检查照片背景下的遮挡、文字对比和颜色收敛，再铺开剩余主题。
