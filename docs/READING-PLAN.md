# 阅读清单模块 · 设计方案(讨论稿)

> 状态:**v1 已实装**(2026-10-11 当日定稿当日落地;verify+115/117 测试+隔离冒烟全绿;含用户新增的**标签筛选**)。
> 探查结论:`C:/Myself/Obsidian/读书笔记` 为专用库,顶层文件夹=一本书(DMBOK/置身事内),笔记带规整 frontmatter(title/type/area/status/tags/created/updated),每本书有 00-规范 页含书名/ISBN/页数;纯原生 Obsidian 无社区插件,obsidian:// 协议可用。

## 0. 已确认决策(2026-10-11)

1. **v1 零写入**:工作台只读 Obsidian 库,回写/骨架生成全部留 v2 逐项确认。
2. **AI 解读进 v1**:书单+关联+AI 一次交付(原 v1.5 提前)。
3. **元数据纯手动**:书名/作者手填,封面用书名首字磁贴,零联网。

## 0.5 核心设计立场

**Obsidian 是笔记与内容的权威源;阅读清单是书目与阅读状态的管理面。** 工作台不复制笔记内容、v1 不写用户库——关联的意义是:在书单里看到每本书的真实阅读活动(笔记数/最近更新/章节覆盖),一键跳到 Obsidian 继续写,并让 AI 读到你的笔记帮你串概念、出复习题。两层各自管各自擅长的东西。

## 1. 功能清单(v1)

| 功能 | 说明 |
|---|---|
| 书单管理 | 状态机:想读 / 在读 / 已读 / 搁置;拖拽或点击切换;分组书架视图 |
| 进度 | 手动两种粒度:百分比 或 「读到第 X 章」;Obsidian 活动可给出建议值(见 §2.3) |
| 评分与短评 | 1-5 星 + 一句话短评(存工作台侧,不进库) |
| 标签 | 自由标签(如:技术/经济/考试),与库内 tags 体系独立、互不干扰 |
| Obsidian 关联 | 配置读书库路径 → 扫描顶层书文件夹 → 一键导入/关联;关联后展示笔记数、最近活动、章节树、笔记成熟度 |
| 打开笔记 | 书详情内笔记索引树,点击任一篇经 `obsidian://open?vault=读书笔记&file=...` 在 Obsidian 打开 |
| 手动书目 | 书单是**超集**:库里还没有笔记文件夹的书(纯想读)也能录入,将来再一键关联 |

## 2. Obsidian 关联设计(核心)

### 2.1 路径配置
- 2026-10-16 修正：每次点击「从库导入」都先显示路径确认框，预填已保存的本地路径并允许修改；「关联并扫描」校验通过后才记住路径并进入勾选导入。路径表单取消、空值或扫描失败不覆盖已有配置；首次关联使用同一表单。当前仍是单库，修改路径会更新已有书目的笔记来源。
- 首次进入空态引导「选择读书笔记库文件夹」;存工作台自有设置(照 AI 配置先例,不进全局设置页)。
- v1 单库(默认建议 `C:/Myself/Obsidian/读书笔记`);多库留 v2。
- 校验:所选文件夹含 `.obsidian` 才视为合法库。

### 2.2 发现与关联
- **扫描**:主进程读库顶层目录(仅一层),每个含 .md 的文件夹 = 书候选;解析其 00-规范/笔记规范类页面提取书名(回退:文件夹名)。
- **导入**:书单「从 Obsidian 导入」→ 列出库中书(含笔记数/最近活动)→ 勾选导入;已在书单的书显示「已关联」。
- **变更感知**:每次进入页面扫描(轻量,只读目录名+frontmatter 头部);新书夹出现→提示导入;文件夹改名/删除→关联条目标记「库中未找到」并提供解除或重新关联。

### 2.3 读取(全部只读)
- 每本书聚合:笔记总数、最近更新时间、章节文件夹列表(即目录树)、笔记成熟度分布(草稿/成型)、规范页摘要。
- 阅读状态建议:新导入时按活动推导初始状态(有近期更新→在读;仅欢迎页→想读),用户可改。
- 进度建议(v1.5):按「已建笔记的章节数 / 规范页声明的总章数」提示,一键采纳。

### 2.4 打开跳转
- `shell.openExternal('obsidian://open?vault=<库名>&file=<相对路径去.md>')`;库名取库文件夹名;失败(未装 Obsidian)给中文提示。
- 另提供「在资源管理器中显示该书文件夹」兜底。

### 2.5 写入边界(v1 = 零写入)
- 工作台**不创建、不修改、不删除**库内任何文件。
- v2 讨论项(默认不做):①回写阅读状态到规范页 frontmatter;②从书单「新建书笔记骨架」在库内生成文件夹+规范页模板。两者都动用户库,须逐项单独确认后才做。

## 3. AI 能力(v1 内交付,复用现有协助对象架构)

- 新 scope module `'reading'`:协助对象 = 某本书;上下文注入 = 规范页摘要 + 最近 N 篇(≤12)笔记的标题与 abstract(callout 一句话),笔记正文按需经只读工具 `read_book_note(path)` 读取(照 ziwei_horoscope 先例,避免整本塞上下文)。
- 「AI 解读」按钮场景:串联概念出思维导图式总结 / 出自测复习题(DMBOK 考试场景直接可用) / 结合短评讨论一本书。
- 参考资料机制天然支持跨书对比(如 DMBOK vs 另一本数据治理书)。

## 4. 数据模型与架构

```
shared/reading-contracts.ts        Zod:书条目/状态/进度/关联;frontmatter 子集解析器(零依赖)
modules/reading/store.ts           userData/reading-books.json(照 bazi 模式,全量读写+校验)
modules/reading/obsidian.ts        库扫描/书籍聚合/frontmatter 解析(纯函数,主进程调用;路径校验防穿越)
modules/reading/ui/ReadingView.tsx 视图;reading.css(mist 玻璃卡语言,轻场景不做深盘面)
electron/main.ts                   reading:* IPC(list/save/remove/scan/link)
src/nav.ts / contracts.ts          '阅读清单' 转 view 'reading'
```

- 书条目:`{ id, title, author?, status, progress?, rating?, comment?, tags?, link?: { vault, folder }, createdAt, updatedAt }`;扫描所得(笔记数/活动/章节树)不落盘、每次现算。
- 封面 v1 用**文字磁贴**(书名首字+按标签取主题色),不联网抓封面。
